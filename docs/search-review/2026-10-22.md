## 三、今天真正抓到的问题：判据自己会说谎（两处）

功能没坏，但**复盘要依赖的两处证据在说谎**。两处都被实测抓到，都已修。

### 问题 1：来源库同时说一个站「能搜」和「假搜索」

`/api/registry` 里 16 个可搜源中，8 个同时出现：

```
searchable=True   search_fail_why=复核：模板不认关键词（假搜索） / 模板打开的不是搜索页
```

我照着这句话"证据"去查「8 个假站为什么还在扇出」，查了半小时 —— 结论是**库是好的**：

```
www.384g.com   tpl=/search.php   method=post  body={'s': '{kw}'}        carries_kw=True
www.tadu.com   tpl=/search       method=post  body={'query': '{kw}'}    carries_kw=True
www.zxs8.net   tpl=/search.html  method=post  body={'s': '{kw}'}        carries_kw=True
...  16 个站全部 carries_kw=True（其中 5 个走 POST body，URL 上当然看不到 {kw}）
```

根因：`search_fail_why` 说的是「**那一个**模板为什么被撤」，而 `save_search_tpl()`
在重学成功后只清了 `search_fail` / `search_hit` / `search_shape`，**没清 why**。
旧结论就这样挂在了新模板上，一挂就是好几天。

> 这条判据为什么没抓到它？—— 不是漏项、不是太松，是**它读的字段本身过期了**。
> 修法：重学成功时把 why 一起清空（`app/registry.py`）。

### 问题 2：「联网核实超预算」不报还欠几个

线上原文只有半句话：

```
00:10:36  novel.engine: 联网核实超预算，先用已有结果
```

复盘时**分不清**两种处置完全相反的情况：
① 12 个候选全核完了、只是都不可用 → 该换搜索词；
② 还有 11 个压根没核 → 该加预算。
而这条日志出现在 16.7s —— 命中其实 3.9s 就拿到了，那 12.8 秒花在谁身上也不知道。

> 违反的是既有纪律「收手可以，不许沉默地收手」。
> 修法：日志和前端提示都带上 `已核/共几个 / 还剩几个`（`app/discovery.py`）。
