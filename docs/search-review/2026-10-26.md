## 二、根因 A：两字书名的「确切命中」把噪声当正主

真机证据（线上 `/api/search`，修复前）：

```
搜《兄弟》 item 流：
   嘿兄弟    score=92  tight=True  tightness=1.0   ← 不是余华那本
   兄弟盟    score=92  tight=True  tightness=1.0   ← 也不是
   兄弟      score=100 tight=True  tightness=1.0   ← 正主（kunnu8，晚半秒到）
```

根因在 `relevance.tightness()` 的容差：

```python
allow = max(1, len(kw) // 3)     # 两字书名 → 也允许「多一个字」
```

两字书名多一个字就是另一本书（`嘿兄弟`/`兄弟盟`/`虫海围城`），可它俩被判
`tightness=1.0`。一条判据错了，三处后果：

1. `rank()` 一看到有 tight 就 `kept = tight` —— 把其余候选全丢。正主晚回来
   半秒，用户看到的就是两本错书；
2. `engine` 的收手门 `_tight_ok = tight_streamed > 0` 用的是同一个 tight →
   1.7s 就收手，慢源（kunnu8）的正主**根本没机会回来**；
3. `search.done` 上写着 `确切=2` —— 复盘时这行**看起来是成功**。

这就是 10-24 那个洞（「够多 ≠ 够好」）在短书名上的**残余**：当时加了「至少
一条确切命中」这道门，而门本身对两字书名是漏的。

**修法**：`allow = 0 if len(kw) <= 2 else max(1, len(kw) // 3)`。
括号/序号仍是版本信息不算多字 —— 「兄弟（余华 著）」「【3】兄弟」照旧算确切。

**上线后线上实测**：

```
嘿兄弟   tightness 1.0 → 0.5  tight=False
兄弟盟   tightness 1.0 → 0.5  tight=False
兄弟     tightness 1.0        tight=True   （web 102 分 + registry 100 分 ×2）
done: 候选=3 确切=3 成书=1
```

## 三、根因 B：熔断退避的 `streak` 每次重启都归 1

文件头写着「连挂的轮数越多冷却越长（15m → 30m → 60m … 封顶 8h）」，
但线上三天，**每次 ship 之后都倒退**：

```
10-23 09:06  源 wikisource 熔断 15 分钟
10-23 10:06  源 wikisource 熔断 15 分钟      ← 一小时后又从 15 分钟开始
10-24 09:04  源 wikisource 熔断 30 分钟
10-24 09:51  源 wikisource 熔断 15 分钟      ← 倒退
10-25 09:07  源 wikisource 熔断 30 分钟
10-25 09:50  源 wikisource 熔断 15 分钟      ← 倒退（09:48:26 服务重启过）
```

根因：`_save()` 只写「仍在冷却中」的条目，`_ensure_loaded()` 也只收「仍在
冷却中」的 —— 冷却**到期那一刻**，条目既不落盘也不再读回，`streak` 跟着没了。
后果不是"日志难看"：死源（wikisource / xbqg5200）每小时被放回名单试 4 次，
每次都让一次真实搜索陪它等满 6s 墙钟；这一天日志里 110+ 条
`handshake operation timed out`，救回来的 0 次。

**修法**（写、读两侧都修 —— 只修一侧等于半修）：

- `_save()`：到期但没被证实恢复的条目也写下去（`until=0`，留 streak/死因/时间戳）；
- `_ensure_loaded()`：这类条目**不进账本**（`snapshot()`/`open_sources()` 看不见，
  面板上不会有幽灵记录 —— 原来那条反向断言仍然成立），而是进 `_memory` 失败史；
- `note_fail()`：账本里没有但失败史里有时，接着上一轮的 `streak` 退避，并按
  「半开试探」处理（一次失败就重新熔断，不必再攒两次）；
- `note_ok()` / `reset()`：连失败史一起清（抖动型的源不能被一路按封顶 8 小时）；
- 失败史 7 天（`FORGET_AFTER`）作废：一周前的死因不该决定今天的冷却；
- 读回时打一行日志，把「想起了什么」说出来。

**上线后线上实测**：

```
21:46:34 novel.health: 熔断器读回落盘：仍冷却 0 个（-）；已到期但保留失败史 2 个（wikisource(streak=2), xbqg5200(streak=1)）
21:46:42 源 wikisource 连续失败，熔断 1 小时（…handshake operation timed out）   ← 旧口径这里会是「15 分钟」
21:46:48 源 xbqg5200 连续失败，熔断 30 分钟（_HTTP 403）                          ← 旧口径也是 15 分钟
```
