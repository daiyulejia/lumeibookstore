看着像头一回，其实是第 6 回。

### 根因：把「模板的账」和「站的账」记成了一本

`app/registry.py` 里写着这句承诺：

> 重学仍不行就由 `SEARCH_LEARN_MAX_TRIES` 自然放弃 —— **有终点，不会每晚白查。**

终点到不了：

1. 模板被判死 → `search_fail += 1`（=1）；
2. 夜里学站成功 → `save_search_tpl()` 执行 `search_fail = 0`（"学会了，失败账清零"）；
3. `should_try_learn()` 的放弃门槛读的**正是** `search_fail` → 永远 0/1 < 3 → 永远允许再学。

而 `search_fail` 本来是「**这份**模板学了几次没学会」，清零本身没错（换模板＝换假设）。
错在拿它当「这个站还要不要学」的预算闸门 —— 那是**站级**事实，不随模板变化。

### 逐站实测：重学救不了它们中的任何一个（今天在服务器侧逐个验）

这就是"每天循环"能一直转下去的原因。

### 判据（正反都验）

- 判死 **1** 次不算惯犯 → 仍允许再学一次（不许一次失误就停）
- 判死 **2** 次 → `should_try_learn()` 为 False、不在 `learn_candidates()` 里
- 冷却 **7 天到期** → 重新允许（不是永久拉黑）
- 重学成功 **不许**清 `tpl_dead`（否则闸门永远不触发）
- **搜出过东西的站** `tpl_dead` 恒 0（闸门天然只打在 `search_hit==0` 的站上）
- `tpl_dead` 必须落盘（否则每次部署重启＝清零，循环照旧）

### 反证（`tools/mutate.py 学站循环`，4/4 全抓，源码逐字节还原）

| 突变 | 被哪条断言抓住 |
|---|---|
| 闸门关掉（判死多少次都照样重学） | ✗ 判死两次之后不许再学 / ✗ 不在学站候选清单 |
| 作废时不记站级账（`tpl_dead` 恒 0） | ✗ 判死一次 tpl_dead=1 / ✗ 重学不许清计数 |
| 重学成功时把 `tpl_dead` 清零 | ✗ 重学不许清计数 / ✗ 判死两次 tpl_dead=2 |
| 冷却期设成 0（等于不冷却） | ✗ 判死两次之后不许再学 / ✗ 不在学站候选清单 |
