## 二、主线：一次冷门书搜索会**顺手废掉搜索源**，而日志一个字都不说

### 2.1 现场（10-30 09:21，我自己踩出来的）

我按流程复现三本冷门书（乡土中国 / 素食者 / 我的阿勒泰），只搜了**这三次**，线上当场发生：


**8 个站的搜索模板被清空，可搜源 22 → 15。** 而当天的 `search.done` 里只有
`候选=0`，源池缩水这件事**一个字都没有**——是靠事后 diff `registry.json` 才发现的。

机制：`_search_one` 抽不到书链接时记一次 `search_shape`，连记 3 次
（`SEARCH_SHAPE_MAX`）就把模板作废。三本冷门书 = 三次 0 产出 = 恰好到顶。

### 2.3 修完还剩一个：杰奇 CMS 的限速页

第一趟 ship（09:54）后立刻复跑同一批冷门书：

```
源池=15→15   源池=15→15   源池=15→14
```

7 个救回来了，仍掉 1 个：`www.jcxs.cc`。抓它的页才看清：

```
错误原因：对不起，两次搜索的间隔时间不得少于 30 秒
```

杰奇 CMS（`/modules/article/search.php?searchkey=`）对同一 IP 限速 **30 秒一次**。
限速页一条书链接都没有、没有空态文案、不回显关键词 —— 长得和「根本不是搜索页」
一模一样，于是连记 3 次形态失败、模板作废。**而这个站 09:54 才刚重学回来，
09:55 又被判死第二次**（就是 `15→14` 里那一个）。

修法：`_looks_like_busy_page()`（间隔时间 / 两次搜索 / 访问过于频繁 / too many requests），
命中时**什么都不记** —— 既不是「站里没这本书」（不涨 `search_miss`，那会让复盘以为这站覆盖窄），
更不是「模板坏了」（不涨 `search_shape`、不作废模板）。

## 三、举一反三

**① 同类站还有几个会中招？** 今天死的 8 个里有 3 个是杰奇 CMS
（`kudushu` / `gashuw` / `jcxs`，模板都是 `/modules/article/search.php?searchkey=`）
—— 杰奇是全网最大的小说站程序之一，**限速 30 秒是它的默认行为**。
现在已由同一条件挡住（预计还影响 0 个：已重新学的 jcxs 连搜 9 次没再死）。
其它两种死法（空态文案 / 关键词回显）由 10-29 的判据覆盖。

**② 这条判据为什么没抓到它？** 因为此前的判据链上**没有任何一环在问"这次 0 产出
是我们自己的问题，还是这个站的模板的问题"**：
- `_looks_like_empty_result` 只问"页面像不像搜索页"，不问"我们是不是被限速/被拦"；
- `search_shape` 只数次数，不区分死因；
- **`search.done` 里没有"源池掉了几个"这一格** —— 用户能感知（以后搜别的书会搜不到），
  日志里却零字段。

第三点是今天补的：`search.done` 增 `源池=A→B`（`stats.pool_before` + 收尾再数一遍）。
