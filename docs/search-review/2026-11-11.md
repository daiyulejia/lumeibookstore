## 二、主线：**「学会 → 复核判假 → 再学」的循环没有终点**（11-06 的修复漏了一半）

### 2.1 现场

每夜 03:18 / 03:39 / 03:58（今晚是 03:20 / 03:38 / 03:59）各有一次完整的同一段日志：

```
03:18:12  学会站点搜索: www.hgcha.com → /search/ post(utf-8)
03:18:41  模板不认关键词，判假：www.hgcha.com /search/ —— 真实探测 52 条…
03:18:41  撤掉假搜索模板：www.hgcha.com /search/
03:39:04  学会站点搜索: www.hgcha.com → /search/ post(utf-8)      ← 又来
03:39:31  撤掉假搜索模板：www.hgcha.com /search/
03:58:04  学会站点搜索: www.hgcha.com → /search/ post(utf-8)      ← 又来
03:58:17  撤掉假搜索模板：www.hgcha.com /search/
```

近 10 天日志里，`www.hgcha.com` **学会 24 次、被判假撤掉 24 次**，全部集中在夜间这三个点。
每次一轮要跑学站爆破（6 个候选）+ 复核实测（52 条结果两次采样），一晚三轮 ≈ 60 个请求、
约 40 秒服务端预算，**换来零个可搜源**。

### 2.2 根因：闸门只装了一条路

11-06 给这个循环装了闸门：站级账 `tpl_dead`（跨模板累计）+ `TPL_DEAD_MAX=2` + 7 天冷却，
`should_try_learn()` 读到就停。但 `tpl_dead` **只在一个地方被 +1** ——
`note_search_result()` 里「连续 3 次打开的不是搜索页」那条路。

夜间复核判假走的是**另一条路**：`discovery.reverify_sites()` → `registry.clear_search_tpl()`。
那里只把 `search_fail` +1，而下一轮 `save_search_tpl()`（"学会了，失败账清零"）又把它清零：

```
03:18  学会 → save_search_tpl()  → search_fail = 0
03:18  判假 → clear_search_tpl() → search_fail = 1
03:39  学会 → save_search_tpl()  → search_fail = 0      ← 门槛永远够不到 3
```

线上库的状态就是铁证：`www.hgcha.com` 的 `tpl_dead` 这个键**从头到尾没被创建过**（`None`），
`search_fail` 永远是 1 —— 日志天天写「已失败 1 次」，看着像头一回。

### 2.3 修法

- `clear_search_tpl()` 累加 `tpl_dead` / `tpl_dead_at`，并打一行点名 + 累计次数：
  `撤掉搜索模板 www.hgcha.com（复核：模板不认关键词（假搜索））—— 该站累计被判死 1 次`。
- 为什么这里**该**记站级账：`search_fail` 说的是「**这一份**模板学了几次没学会」，换模板就重记；
  `tpl_dead` 说的是「**这个站的搜索页**对我们有没有用」—— 判假撤模板证的正是后者，
  换一份模板不会让一个不认关键词的搜索页变得认关键词。

| www.lqbook.com / www.jseea.cn / www.3qdu.org / www.16zw.com | 各 1 | 不会再学（`should_try_learn` 被别的条件挡住），本次修复后会各记 1 次 `tpl_dead`，不影响 |

修复后 hgcha 的账变成：今晚 1 次 → 明晚再 1 次 → 到 2 进 7 天冷却。
**从「每晚 3 轮、永久」变成「两晚各 1 轮，然后一周不碰」**。

### 3.2 同一个母题还剩一处：**「判不出结论」的复核永远在重试**

`模板复核完成：查了 7（…）撤掉 1，留下 0，没结论 6` —— 这条每晚出现三次，几乎一字不变。
`没结论 6` 是 350.ooo / m.kudushu.org / www.bqg5555.cc / www.hodei.net / www.maozhuar.com / www.nana00.com：
它们「真词 0 条、控制词 0 条」，`judge_by_control` 三态判据给不出结论，于是**每晚重查、永不终止**。
成本 6 站 × 3 轮 × 2 个探测词 ≈ 36 个请求/夜，比 hgcha 小一个量级，但**是同一类病**：
判据给不出结论 ≠ 值得再查一遍。

今天不动它（要新增「复核无结论」计数 + 冷却，是第二个机制，风险与收益不匹配）。
留作欠账，量已经量好了。
