## 三、主线：三个 host 占着 30% 的源池，被判中 58 次也不走

### 3.1 现场

`/api/registry` 的 `stats.sites_searchable = 10`，逐个看账本：

```
sk.3qdu.org   healthy=True searchable=True kwblind=31 fail_shape=31 search_hit=1
sk.3qdu.com   healthy=True searchable=True kwblind=47 fail_shape=47 search_hit=1
sk.3qdu.net   healthy=True searchable=True kwblind=58 fail_shape=58 search_hit=0
```

三个 host 的 `name` 都是「3Q中文网」、`search_tpl` 都是 `/?s={kw}` —— **同一个站的
三个入口**，合起来占 10 个名额里的 3 个（30%）。

`search_kwblind` 是 11-18 加的字段，含义是「换了控制词，它还抽回一屏书」。
数字都 31/47/58 了，处置却一次都没发生。

### 3.2 实测：它真的不认词

同一台机器、三个关键词打同一个地址：

```
sk.3qdu.net  kw=三体                  status=200 len=13024 booklinks=42
sk.3qdu.net  kw=斗破苍穹              status=200 len=13049 booklinks=42
sk.3qdu.net  kw=zzqqxxbukCunZaiDeShu  status=200 len=13062 booklinks=42
sk.3qdu.org  …三个词同上…             全部 42 条、标题都是「推荐小说/玄幻小说/仙侠小说/都市小说」
```

**42 条 == 42 条 == 42 条**。它把 `?s=` 当空气，回的是整站推荐位。
所以那 31/47/58 次判定是**对的**，问题在于"判中了不动手"。

### 3.3 根因：一次偶然命中，关掉两条出口

```python
# app/registry.py（修前）
if (int(cur.get("search_hit") or 0) == 0        # ← 出口①：要求"从来没搜出过东西"
        and int(cur.get("search_shape") or 0) >= SEARCH_SHAPE_MAX
        and (cur.get("search_tpl") or "").strip()):
    ...模板作废...

def needs_keyword_control(host):                # ← 出口②：同样要求"从来没搜出过东西"
    return int(s.get("search_hit") or 0) <= 0
```

不认词的站回的是整站最新更新，用户搜的那本书**碰巧在列表里**时 `search_hit` 就 +1。
于是：

- 出口①关闭 → 模板永久免疫，无论再被判中多少次；
- 出口②关闭 → 连"再问一句控制词"都不做了，`search_kwblind` 从此不再增长
  （`.org`/`.com` 的 31/47 就停在那儿，`.net` 的 `search_shape` 卡在 2，
  离死刑线 3 差一票）。

**两个独立判据共用了同一个前提 `search_hit == 0`，而这个前提在一次偶然命中后
就永久为假。** 这和 11-17「只进不出的判据 = 资产单向缩水」是同一个母题，
只是方向相反：那次是"越线即冻结"，这次是"过线即免疫"。

### 3.4 修法

| 改动 | 位置 |
|---|---|
| 新增 `KWBLIND_MAX = 2`（判中两票即作废模板），连同"为什么不能跟 `search_shape` 合并"的现场写进注释 | `app/registry.py` |
| 作废条件拆成两支：`_shape_dead`（仍要求 `search_hit == 0`）**或** `_blind_dead`（不要求） | 同上 |
| 死因分成两句：「模板不按关键词过滤」/「模板打开的不是搜索页」 | 同上 |
| 重学成功时一并清 `search_kwblind`（新模板＝新假设，不许替旧模板背债） | `note_search_tpl()` |
| 控制实验入口放宽成「`search_hit == 0` **或** 已经被抓过一次」—— 否则"抓过一次+偶然命中"仍是一辈子的免疫 | `needs_keyword_control()` |

为什么是**两票**而不是一票：`_ignores_keyword()` 的判定虽然保守（控制词要 ≥ 真词的
80% 且 ≥ 8 条），但终究只是两次抓页的比对。留一票余量，宁可让真坏的模板多白打
一轮，也别把好源错杀（10-29 的教训：一天废掉 8 个模板，源池 22→14）。

为什么 `_shape_dead` **仍然**要 `search_hit == 0`：那条说的是"打开的不是搜索页"，
而拦截页/限速页是**偶发**的 —— 一个真能搜出书的模板不该因为几次坏天气被弄死。

## 五、举一反三（二）：这条判据为什么没抓到它？

答案是**最朴素的那一个：字段有写、没有读**。

```bash
grep -rn "search_kwblind" app/ | ...
→ app/registry.py:1091:  cur["search_kwblind"] = int(cur.get("search_kwblind") or 0) + 1
（此后全仓零读取点）
```

11-18 加这个字段的动机写得很清楚（"不计这一格，两种完全不同的病因在库里长得
一模一样，复盘只能猜"）。但**只记账、不花账**，等于把判断留给了半年后某个早上
的 grep。今天这三站能一直赖着，正是因为没有任何一行代码读它。

### 补的闸门：账本计数器必须有读者

`tools/test_search_ledger.py` 第 6 节（新增）：扫 `app/registry.py` 与
`app/sources/registry_source.py` 里所有 `cur["x"] = int(cur.get("x") or 0) + 1`
形式的累加计数器，要求**同一模块里至少有一处把它当判据读**（比较 / 参与算术）。
只写不读的，测试直接红，并把字段名和行号点出来。

例外必须写进白名单并说明理由 —— 白名单本身就是复盘材料
（"这个字段我明确不参与任何决策" 比 "忘了读" 诚实）。目前只有一条：

```python
"search_miss": "只做展示：「站里没这本书」不许参与任何淘汰",
```

这条白名单也是从文档里抄来的（`note_search_result` 的 docstring 明写
"`search_miss` **永远不参与**任何淘汰"），不是我临时拍的。

⚠ 扫描器自己也要有牙：测试里拿一段**合成**源码（一个只写不读、一个有读者）
喂给扫描器，两种都必须判对。否则"0 个问题"可能只是"它什么都不看"。
