## 四、主线：观测去重窗口是**滑动**的

### 现场证据（本机，11-28 09:19~09:24）

```
09:19:27  站 www.axxsw.net 又一次打开的不是搜索页，但距上次仅 13s（< 180s 窗口）

09:20:08  站 www.axxsw.net …… 距上次仅 17s
09:22:23  站 www.axxsw.net …… 距上次仅 135s
09:22:36  站 www.axxsw.net …… 距上次仅 13s
09:23:03  站 www.axxsw.net …… 距上次仅 27s
09:23:11  站 www.axxsw.net …… 距上次仅 8s
09:23:21  站 www.axxsw.net …… 距上次仅 10s
09:23:26  站 www.axxsw.net …… 距上次仅 5s
09:23:34/38/42/55、09:24:01 …… 4s / 4s / 4s / 13s / 6s
（同段 www.nana00.com 另有 4 次：39s / 25s / 7s / 4s / 22s）
```

**15 次观察，`search_shape` 一次都没涨。**

```json
{"www.axxsw.net":  {"search_shape": 0, "search_shape_at": "162 秒前", "search_hit": 31, "search_fail": 0},
 "www.nana00.com": {"search_shape": 0, "search_shape_at": "163 秒前", "search_hit": 60, "search_fail": 0}}
```

`search_shape_at` 永远只比"现在"早 160 余秒 —— 这不是巧合，是**每一次观察都把它刷新**的指纹。

### 根因

`app/registry.py::note_search_result()` 里：

```python
if _now_ts - _last_shape > SHAPE_BURST_WINDOW:
    cur["search_shape"] += 1
else:
    logger.info("…按同一次观察合并，不计入死刑")
cur["search_shape_at"] = _now_ts      # ← 无条件执行：被合并的观察也刷新锚点
```

180 秒窗口的语义是「同一场风暴只算一次」。但锚点被"最近一枪"刷新后，只要失败间隔
< 180 秒，下一枪又落在窗口里 → 再刷新 → **窗口永远滑不到头**。

设计目标是「16 票压成 1 票」，实际产出是「压成 0 票」——**矫枉过正，方向反过来**：
- 站真坏：永远凑不满 3 票 → 模板永不作废 → 每轮搜索白打一次请求，
  `已返回 N/M 个源` 被它们撑得像"源还很多"。
- 站只是被我们打限速：本来也被压成 1 票，现在压成 0 票 —— 这一半是**对的**（不该判死）。

### 修复

锚点只在**真记了一票**时往下走：

```python
if _now_ts - _last_shape > SHAPE_BURST_WINDOW:
    cur["search_shape"] += 1
    cur["search_shape_at"] = _now_ts      # ← 挪进 if：锚点＝这场风暴的第一枪
else:
    logger.info("…距上次仅 %ds（< %ds 窗口）—— 按同一次观察合并", …)
```

改完：同一场风暴 = 1 票（不是 16、也不是 0），隔过窗口的下一次失败 = 第 2 票。

## 六、举一反三

### ① 同类站/同类源会不会也中招

`search_shape_at` 全仓只有**一个写入点**（`grep -rn "_at\"\] = _now" app/*.py`），
所以"滑动窗口"这个病只有这一处。另外三个带时间戳的字段逐个体检过：

| 字段 | 语义 | 会不会滑动 |
|---|---|---|
| `tpl_dead_at` | "哪一天被判死的"（一次性记录） | 否，写一次就不再动 |
| `reverify_miss_at` | 复核没结论的时刻（纯计数，不参与判定） | 否 |
| `recheck_ok_at` | 复核判真的时刻 | 否 |

**预计还影响 0 个站**（同一处已修完）。但**受害面**（被这个 bug 掩盖的站）今天量到 2 个：
`www.axxsw.net`、`www.nana00.com` —— 它们占 7 个可搜源里的 **29%**，每轮搜索白打一次请求。
修完之后它们**仍然不会被判死**，因为 `_shape_dead` 还要求 `search_hit == 0`
（这两个站历史命中 31 / 60 次）。这条我**没有动**，理由写在下面。

### ② 这条判据为什么没抓到它

因为**压根没有这条判据**，而且既有测试的替身把这个洞**抹平了**：

```python
def _obs(host):                      # tools/test_registry.py 里的助手
    cur["search_shape_at"] = 0       # ← 直接把时间戳清零，模拟"一次独立观察"
    R.note_search_result(host, hits=0, raw=0)
```

它把"时间关系"整个摘掉了，于是「窗口能不能走到头」从来没被测过 ——
真机上跑一万次也永远绿。今天补的 ⑧b 用**真实间隔**（10s / 170s / 181s）去测，
而不是把时间戳清零。

> 同族教训（已进 MEMORY）：「桩要等状态，不要等时长」的另一面 —— 替身不能把
> 被测的时间逻辑一起替掉。

### ③ 今天**没有动**的一处，以及为什么

`_shape_dead` 现在还带着 `search_hit == 0`（历史命中过就免疫形态判死）。
今天 axxsw / nana00 每轮都"打开的不是搜索页"、却因 hit>0 永远死不掉 —— 看起来
和 11-27 修的「不认词靠偶然命中免疫」是同一个坑。但我**没有**去掉这个条件：

- 它们今天的失败**可能是我自己打出来的限速页**（4 分钟 110 次请求）。11-16 的教训
  就是"我们自己把站限流了，却记成源挂了"，处置正好相反。
- 既有判据 ③ 明文写着「搜出过一次 → 之后连续不是搜索页也不作废模板」，
  那是刻意的产品决定（站点会临时拦爬虫），推翻它需要**线上真实流量**的证据。
- 线上 17 天不可达，拿不到那个证据。

→ 记进欠账，等实例恢复后按线上 `source.fail` / `search_shape` 的真实分布再判。
