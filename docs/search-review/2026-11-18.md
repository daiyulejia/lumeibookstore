## 二、主线：不认关键词的模板，永远不会被作废

### 现场（都是真请求，不是推断）

```
www.ldxs1.net（零点看书）  ok=7  down=15  last_ok 754.8h 前（31 天）
www.biqugela.cc（笔趣阁啦）ok=6  down=15  last_ok 887.4h 前（37 天）
```

两个站都在 `probation_sites()` 的候选里，每 6 小时各被试一次，**每次都零产出**，
而且永远出不去 —— 它们占着试用通道 100% 的名额（`PROBATION_MAX=2`）。

逐站手工打真站点，看它到底为什么零产出：

```
ldxs1  GET /search.php?q=斗破苍穹     → 抽出 65 条书链接（全是"最新更新"）
ldxs1  GET /search.php?q=zzqqxxv      → 抽出 62 条（95%）—— 关键词被当空气
tadu   POST /search  query=斗破苍穹   → 88 条
tadu   POST /search  query=zzqqxxv    → **0 条**
384g   POST /search.php s=斗破苍穹    → 100 条
384g   POST /search.php s=zzqqxxv     → **0 条**
```

差别是断崖式的：真站对"肯定没有这本书"回 0 条，`ldxs1` 照吐一屏。

### 根因

`_search_one` 把「抽到一屏书链接、按关键词过滤后一条不剩」**一律**记成
`FAIL_EMPTY`（＝"这个站只是没有这本书"）。对真搜索页这是对的 —— 10-29 的教训
就是把它错判成形态失败，一天废掉 8 个模板、可搜源 22→14。

但对 `ldxs1` 这一族（收下 `?q=` 却回整站列表）就等于：

* `raw > 0` → 永远不记 `search_shape` → **模板永不作废**；
* 模板不作废 → 永远学不到新模板 → **永远零产出**；
* 零产出 + 每次 6 小时冷却 → 永远在试用通道里打转，占着名额不放。

一句话：**「有书链接」被当成了「这是搜索页」的证据**，而它只是"这页上有书"的证据。

### 改了什么

| 文件 | 改动 |
|---|---|
| `app/registry.py` | 新增 `needs_keyword_control(host)`：只对「有模板且 `search_hit == 0`」的站做控制实验；`note_search_result()` 增 `kwblind` 参数，落站级 `search_kwblind` |
| `app/sources/registry_source.py` | 新增 `_ignores_keyword()`：换一个肯定没人用过的词再问一次，控制词抽到的链接 ≥ 真词的 80% 且 ≥ 8 条才判"不认词"；判中走 `FAIL_SHAPE` + `raw=0`（模板才可能被作废）。控制请求失败/被限流一律返回 False |
| `tools/test_site_fault.py` | 新增 ⑩/⑩b/⑩c/⑩d 共 14 条（55 通过 0 失败） |
| `tools/test_registry_source.py` | 假站改成"认关键词"：原来不管搜什么都回同一页，那本身就是不认词的定义，测的是一条不存在的行为（69 通过 0 失败） |
| `tools/mutate.py` | 新增 `认词` 组 5 条突变 |

三条保守线（都在注释里写死了，别再拆）：

1. **只对 `search_hit == 0` 的站做** —— 真资产不为"偶尔没这本书"多打一个请求；
   一次搜索会问十几个站，冷门书让大多数站零命中，闸门放宽就是每轮凭空多十几个请求。
2. **判不出来 ≠ 判假** —— 控制请求打不通、被本地限流挡住、被限速页糊住，一律当"没结论"。
3. **阈值是比例 + 下限，不是">0 条就判假"** —— 真站的"没这本书"页常带一屏推荐位
   （线上 `www.biqusa.com` 就是这样），那类页面抽到的条数远小于真词。

成本是**自终止**的：判中三次 `search_shape` 模板即作废，之后闸门随模板一起关。

## 四、举一反三

**同类站会不会也中招？**
会。凡是"收下搜索参数、却回整站/推荐列表"的站都是同族。10-28 记过的 5 个
（31xss / dushu / kepub / taishuaile / taiminc）就在这一族里 —— 当时只做了
"源头丢弃不含关键词的候选"（用户看不到别的书了），**没有作废模板**，
所以只要它们还活着就一直占着"可搜源"的名额。
预计影响面：本地库 4 个模板站里 **2 个（50%）**；线上最后一次可观测（11-13）
16 个可搜源里这类站的比例**没埋过点**，今天补的 `search_kwblind` 就是量它的。

**这条判据为什么没抓到它？** 三层，一层比一层难看：

1. **判据太松**：`FAIL_EMPTY` 把"站里没这本书"和"模板不认词"合成一笔，
   两种处置完全相反的病因在库里长得一模一样。
2. **压根没埋点**：`raw>0 且 hits=0` 只涨一个 `search_miss`，没有任何数字能分开它们。
3. **清单漏项**：项目里**早就有**控制实验（`sitelearn.judge_by_control`），
   但它开头就写着 `if not hits or not urls: return "unknown"`
   —— **真实命中 0 条时主动弃权**。而"不认关键词"的站恰恰永远 `hits==0`。
   这不是"没工具"，是工具在它最该用的那个场景里自己退场了。
   和 10-31「判据只认一种文体」是同一母题：**判据的适用边界没跟着病型走**。
