# 2026-11-24 搜不到复盘：一次 0 字节抖动把唯一可用的引擎关了十分钟

## 0. 一句话结论

线上实例**第 13 天不可达**，所以「用户搜不到的书」今天**没有数据可判**（不是"没有新案例"）。
改走本机 8000 主动探针，抓到的是一个**不依赖线上流量**的系统性病灶：

> HTTP 200 + **0 字节**（或 14.6KB 空壳页）被 `_refused_cooldown` 判成「被反爬」→
> 必应关 **600 秒**；百度那条又被真反爬打死 → 整整十分钟全网候选供给 0，
> 日志只剩 `各引擎=Bing=0 百度=0` + `联网核=0→0 失败=0 非目录=0`，
> 读起来和"这本书网上没有"一模一样。

已修、已反证、自检全绿；**未部署**（实例不可达）。

## 3. 根因（主线）：抖动被当成封禁，一次抖动 = 十分钟全网静默

### 3.1 证据（本机实测，可复现）

```
# 同一问法连打 5 次（Bing）
0: 共 3 条  非垃圾 3  ['fanqienovel.com','m.guishuji.com','www.pinshuzhai.com']
1: 共 3 条  非垃圾 3  （同上）
2: 共 3 条  非垃圾 3  （同上）
3: ERR 返回异常页（0 字节，不是结果页）        ← HTTP 200，body 就是空
4: ERR 冷却中（598s 后再试）                  ← 之后所有书都是这一行
```

```
# 新建连接池后的头几次请求（3/3 都一样）
bytes=14647  h2=0  b_algo=0  title=搜索 - Microsoft 必应   ← 14.6KB 空壳页
```

两者都被 `_engine_refused` 判成「返回异常页（N 字节，不是结果页）」，
而 `_refused_cooldown` 的分档条件是 **`why.startswith("HTTP ")`** ——
只有 5xx 才算"临时故障"，其余**一律**按「被反爬」停 600 秒。

### 3.2 为什么这次是致命的

- 百度今天实测**是真的被封**：`百度拒绝了我们（被反爬（HTTP 200，2649 字节验证页））`。
  于是候选供给只剩必应一个引擎。
- 一次抖动 = 唯一引擎下线 10 分钟。这 10 分钟里**每一次用户搜索都是 0 条**，
  而且账本上没有任何一行说明原因（`引擎=` 那格压根不打印，因为候选为空）。
- 这是 11-19（百度 `return []`）、11-20（必应 `return []`）同一母题的**第三个形态**：
  前两次合的是"返回值"，这次合的是"**冷却档位**"——
  「一次传输抖动」和「对方封了我们」被写成同一笔，处置相反（重试 vs 等十分钟）。

### 3.3 修法

| 改了什么 | 怎么改 |
|---|---|
| 判据分开 | `refused_transient(why)`：只看**有没有反爬证据**（验证指纹 / 验证域），不看体量。空壳/0 字节/5xx/传输异常 = 抖动 |
| 抖动重试一次 | `_fetch_engine()`：发请求 + 判被拒 + **原地重试 1 次**（0.6s 间隔），第一次空壳第二次正常就照样出结果 |
| 只重试 1 次 | 11-01 的教训：16 个同参请求会把搜索引擎打成"返回别的页面" |
| 冷却两档 | 抖动 → 120s（`BING_ERROR_COOLDOWN`）；被反爬 → 600s 不变 |
| 一份实现 | `_bing` / `_baidu` 都走 `_fetch_engine`（11-19「两个入口只修一半」不再复发） |
| 隐形墙钟 | `ENGINE_TIMEOUT = 8.0`（`get_client` 默认 25s = 整轮联网预算 32s 的 78%） |
| 账本补 `拒=` | `search.done` 的 `联网核=` 与 `联网核实账` 都点名"谁拒绝了我们" |

## 4. 举一反三

### 4.1 同类源会不会也中招？

| 同类入口 | 结论 |
|---|---|
| 百度 | **同一条路，已一起修**（`_fetch_engine` 共用），测试按 `ENGINES` 表遍历覆盖 |
| 其它全局禁用点 | `grep -rn "_blocked_until\|startswith(\"HTTP\")" app/` → **只有 websearch 一处**，已收敛 |
| 站点记账（`site_fault_why` → `is_healthy`） | 单次失败只涨 1 分，`down>=3 且 down>2*ok` 才判死 —— **不会因一次抖动判死**，不动 |
| `errors.LocalCooldown`（我方限流） | 11-16/11-17 已分开归因，今天复核仍在 |

### 4.2 这条判据为什么没抓到它？

- **不是清单漏项**：`test_websearch.py` H 组早就在遍历 `ENGINES`，也断言了
  「3KB 空壳要抛 EngineBlocked」——但它只断言**抛不抛**，没断言**冷却落哪一档**。
- **是判据太松**：`⑤ 5xx 的冷却 ≤ ERROR_COOLDOWN` 只覆盖 5xx 这一种"临时故障"，
  而 0 字节/空壳走的是另一条分支（`返回异常页`），从来没人问过它落哪档。
- 补的判据：`test_websearch.py` ⑨ 组 12 条 —— 重试次数用**请求计数**断言、
  冷却只断言"落哪一档"（不量墙钟）、反向三条（验证页不许重试 / 验证页必须长冷却 /
  正常页不许留冷却）。账本格子在 `test_toc_anchor.py` 加 4 条。
