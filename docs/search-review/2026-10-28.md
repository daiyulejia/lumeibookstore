## 三、根因：5 个「轮换列表」假站（14 个可搜源里的 5 个，36%）

`www.31xss.com` / `www.dushu.co` / `www.kepub.net` / `www.taishuaile.com` /
`www.taiminc.com` 的"搜索页"**不认关键词参数**，照常回一页「最新更新」，
而且**每次都换一批**。三个连环后果：

1. **判假判不掉**：控制实验问的是"换个搜不到的词，结果集**变不变**"。
   轮换列表每轮都不一样 → 两次 URL 集合永不相同 → 恒判"真" → 盖章免检。
2. **记账记反了**：`search_hit` 只数"有没有东西回来"，它们每次都回 5~6 条 →
   `search_hit` 涨到 100~260，库里看它们是**最健康**的站。
3. **排序把它们排最前面**：`RegistrySource.search()` 按 ok 排序 → 每次搜索先问它们，
   先把 29 条无关候选倒进候选池 → `候选=52 确切=0`，用户点开是**别的书**。

用《素食者》线上原样：`09:09:08 候选=3 确切=0 可读=1 耗时ms=22004` —— 撞满 20s 扇出，
等满一整轮，换回来的还是无关条目。

## 四、改法：不动"哪个站算可搜源"，动"什么能当候选"

被判假的判据**试过、否决了**（有实测依据，写进代码注释了）：给控制实验补一维
「结果页标题里有没有这本书」，会**误杀真站** —— `www.biqusa.com` 搜自己库里的
书名也抽不出标题（它对搜不到的词的返回一页推荐位，抽出 50 条全无关），当场被判假。

所以改在源头 `RegistrySource._search_one`：**标题和作者里连一个搜索词都没有的条目，
一条都不许进候选池**。这条判据不依赖"先认出哪里是假站"，将来新冒出来的假站自动被挡。

| 文件 | 改动 |
|---|---|
| `app/relevance.py` | 新增 `kw_terms()`：关键词按词拆 + 归一化（繁转简/去标点/剥 SEO 尾巴）+ 丢单字词；一个不剩时回落原词 |
| `app/sources/registry_source.py` | `_search_one` 加源头过滤 + "含关键词的排前面"改用词表；新增 `_mentions()`（标题 **或** 作者命中即留） |

三个反向陷阱都钉了断言（写的时候全踩过）：

- **按整串比对** → 搜「余华 活着」时 `余华活着` 谁都不含，**14 个站全部清零**；
- **只看标题** → 搜作者名时书名里当然没有作者名，全站清零；
- **不丢单字词 / 不回落** → 单字查询会把过滤器废掉（什么都算命中）或全清掉。
