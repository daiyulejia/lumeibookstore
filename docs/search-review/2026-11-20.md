## 三、主线根因：必应被拦时也静默返回空（11-19 欠账②）

```python
def _bing(keyword):
    out = []
    r = get_client().get("https://cn.bing.com/search", params={"q": keyword}, ...)
    if r.status_code != 200:
        return out          # ← 403 / 429 / 502 全在这里变成"没这本书"
```

11-19 只修了百度（拿到「百度安全验证」时抛 `EngineBlocked`），必应这一行原地躺了一整天。
后果与百度那条一模一样：一个 `[]` 同时代表

* 「这本书必应上确实没有」→ 该去问别的引擎；
* 「必应把我们拦了 / 它自己坏了」→ 该等冷却、换出口。

两者处置相反，而日志里只剩聚合行 `Bing=0`。今天的账本里 `引擎=bing4,baidu3`
是个反例证明：必应好使的时候它能给 4 条候选 —— 一旦它 403，这 4 条会**静默消失**，
而复盘看到的是"候选只有 3 条"，读起来像"这本书冷门"。

### 判据为什么没抓到它（第二个问题比第一个重要）

11-19 是**按上一次改过的符号 grep** 的（`_baidu`），于是只改了百度。
更深的窟窿是：引擎列表是硬编码元组字面量

```python
for name, fn in (("Bing", _bing), ("百度", _baidu)):
```

**没有一份"所有引擎"的清单可遍历**，所以"同类还有几个"这个问题根本无处验证 ——
只能靠人记得。今天改成登记表（只存全局名，避免 import 时把函数绑死）：

```python
ENGINES: tuple[tuple[str, str], ...] = (("Bing", "_bing"), ("百度", "_baidu"))
```

判据按表遍历：每个引擎都要在「403 / 200+3KB 空壳」上抛 `EngineBlocked`。
以后加第三个引擎，没接判据就当场报红。

### 改了什么

| 文件 | 改动 |
|---|---|
| `app/websearch.py` | 新增 `_engine_refused()`：状态码 + 体量 + 验证指纹三者合一；`_bing` 接上（抛 `EngineBlocked` + 冷却 600s / 5xx 120s，冷却期内不发请求）；`_baidu` 改为复用同一份实现，不再手写第二遍；`ENGINES` 登记表；全员被拦时明写一行「2 个引擎全部拒绝了我们，本轮候选供给为 0（不是「网上没有这本书」）」 |
| `tools/test_websearch.py` | I 组 17 项（按 ENGINES 遍历 + 5 条反向） |
| `tools/mutate.py` | 新组「引擎静默」5 条；「候选供给」那条靶点重锚（原靶点随重构消失） |
| `tools/ship.py` | 该套件标签加「引擎静默」，说明它现在管两件事 |

阈值不是拍脑袋，是本机实测：

* 必应正常结果页 **103~105KB**，连乱码词 `zzqqxxvvbbnnmmjjkkllppooiiuu` 都是整页 10 个链接
  → 「200 但 <20KB」必然是异常页，而不是"这个词真没结果"；
* 百度正常页 40~100KB、验证页 2649 字节，阈值沿用 5000 / 20000（`wall_max` 不改小，
  否则 5~20KB 的真结果页会被当验证页扔掉）。

### ③ 我自己踩的坑（写下来免得再犯）

第一版 `_engine_refused` 只扫正文**前 4000 字**（`body[:4000]`），于是既有那条反向判据
「大结果页里夹着『请输入验证码』不许判被拦」变成了**空转** —— 验证字样在 30000 字之后，
压根没扫到。当场被「只看指纹不看体量」那条突变抓出来（存活）。

> **判据的窗口也是判据。** 截断正文、只看头部、只取前 N 条，都会让下游断言变空转。
