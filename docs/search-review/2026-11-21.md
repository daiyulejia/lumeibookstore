## 三、主线根因：《乡土中国》不是缺书，是我们把它判死了

### 死的哪一段：③ 核实（不是①站内搜、也不是②联网发现）

天涯书库那一页 `https://www.tyshu.cc/wenhua/8127/` 就是它的真书目页：

```
标题《乡土中国》在线阅读/全文阅读(费孝通) - 天涯书库
序言 / 旧著《乡土中国》重刊序言 / 乡土本色 / 文字下乡 / 再论文字下乡 /
差序格局 / 系维着私人的道德 / 家族 / 男女有别 / 礼治秩序 / 无讼 /
无为政治 / 长老统治 / 血缘和地缘 / 名实的分离 / 从欲望到需要 / 后记
```

17 篇，地址 `/wenhua/8127/333956.html` → `333972.html` **连续编号**。
书在那里，我们也能读。三个独立的原因把它锁死了：

### 原因 ①：目录判据要求「页面自己写目录」

10-31 加的第三条证据是「页面写着「章节列表」+ 链接挂本书下 + 是主要链接群」。
这一页**一个「目录」字样都没有**（`grep -c 目录 = 0`），标题也不叫「第N章」
→ `toc_quality` 给 0.35 → `kind=unknown`。

判据只认一种**文案**，就等于只服务一种页面。10-31 修的是"散文集没第N章"，
但修法绑在"页面自述"上，散文集页面不写这句话就又漏了。

### 原因 ②：一次判错 → 永久放弃

`_verify()` 见 `not is_healthy(site)` 就 `return None`，**一个请求都不发**。
`FAIL_SHAPE` 记三次就过死亡线（`fail=3, ok=0`），于是 `www.tyshu.cc` 从 11-19
起一直在"死站"名单里 —— 而它当初被判死的原因，恰恰是我们没认出目录。

### 原因 ③：用户等的这条路上没有复活通道

11-17 给「学站」补了 `probation_sites()`（试用通道、6h 一次、一次成功即复活），
但**核实候选**这条路没有。同一母题的第二个入口没接上 ——
「闸门装在一个入口上，就等于没装」。

### 改了什么

| 文件 | 改动 |
|---|---|
| `app/webfetch.py` | 新增 `_own_toc_block()`：第四条目录证据，**不依赖页面文案**。四条同时成立：整组链接 ≥95% 挂在本页这本书下 / 是页面主要链接群（≥50%）/ URL 有单调数字列 / **书本路径至少两段**。认出来给 0.85 分（页面自述那条仍 0.9），标记 `_own`，`analyze()` 出口与 `_anchor` 一起摘掉 |
| `app/registry.py` | `worth_recheck()`：只有"失败全在形状上、一次网络失败都没有、也没被 offtopic/video 否决"的站才值得复核；`note_recheck_ok()`：复核成功就结掉 `fail_shape` 并**同步扣减** `fail`（只清分桶不扣总数，健康判据读的是 `fail`，账结不掉） |
| `app/discovery.py` | `_pick_recheck()`：**活候选 <2** 时挑一个复核，每轮最多 1 个，且在**建线程表之前**定（进线程抢会让同一输入的账随调度变，判据就没法写）；`_verify(force=)`；核实账那行加 `复核=N(名字)`；核实循环里"意料之外的异常"从 `debug` 提到 `INFO` 并带 host |
| `app/engine.py` | `search.done` 的 `联网核=` 新增一格 `复核=N(名字)` |
| `tools/test_toc_anchor.py` | F 组（结构证据，正例=真实页面快照、反例=分类页/章节页/`猜你喜欢`）+ G 组（复核通道：值得/不值得、名额开关、结账、接线），46 → 49 项 |
| `tools/test_websearch.py`、`test_discover_async.py` | 三个 `_verify` 替身补 `**k`（见第五节） |
| `tools/fixtures/tyshu_toc.html` | 真实页面快照（13893 字节，未改动），`grep 目录 = 0` |
| `tools/mutate.py` | 新组「目录结构」3 条 +「死站复核」2 条 |

### 为什么这条判据以前没抓到它

10-31 的夹具（`shubaoc_toc.html`）**页面里写着「章节列表」**，所以那条测试
只证明了"页面自述"这一路能走通。没有一份"是真目录、但不写目录"的夹具 ——
判据覆盖的是文案，不是页面结构。今天补的就是这一份（真实页面快照）。

**今天真正的受害者 = 1 个**（tyshu）。其余 4 个逐个抓过，判死是对的 ——
这也是复核通道收窄的价值：它每轮只花 1 个槽，挑的还是"我们可能判错"的那类。

误判面（新判据会不会乱开火）也扫了三个非目录页：
`/wenhua/8127/333958.html`（正文页）、`/wenhua/`（分类页）、站点首页 ——
新判据**一次都没开火**（正文页链接数不够、分类页路径只有一段）。

### ② 仍然会漏的形状（写清楚，别假装全覆盖）

* 目录**少于 8 条**的短篇/散文单篇（`min_items=8` 是硬门槛）；
* 书本路径**只有一段**的站（`/book1234.html`、`/read.php?id=1`）—— 这条为了
  防分类页误判加的，代价就是这类站认不出；
* 目录**不占页面多数链接**（侧栏推荐比正文目录还多）—— 50% 门槛过不去；
* 目录靠 **JS 渲染**（首页 2481 字节那类）—— 我们只解析 HTML。

### ③ 顺带修掉的一个"沉默"

给 `_verify` 加 `force=` 之后，三个老的测试替身签名不匹配，抛出的 TypeError
在核实循环里被 `logger.debug` 吞掉 → 账本只剩「候选=12 不是目录=0」，
读起来像"这些站都不行"，实际是"我们自己的代码在这几个候选上崩了"。
现在这条异常是 `INFO` 且带 host。判据那边三个替身统一改成 `**k` ——
2026-10-31 已经因为同一个原因踩过一次（那次只改了一个替身）。
