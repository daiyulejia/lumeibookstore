# 噜妹书院 · 品牌与界面设计规范

> 这份文档是**设计决策的唯一依据**。改 UI 之前先读它；
> 任何「我觉得可爱就加上去」的改动都不算数 —— 一切以本文档的内核与规范为准。
>
> **v2 修订（重要）**：v1 版本基于百度百科的文字描述 + 写实水豚照片，
> 把噜噜画成了**浅棕色 2D 扁平水墨水豚**。在拿到真实 IP 素材比对后，
> 确认这是**根本性错误** —— 「水豚噜噜」的真实形象是 **3D 渲染的明亮橙黄色毛绒水豚**。
> 本版本已按真实 IP 全面重做，v1 的配色与造型全部作废。

---

## 一、内核：噜噜和噜妹到底是谁

上一版最大的错误是**望文生义**：以为「噜妹」= 一个可爱的妹系吉祥物，
于是画了个粉色圆脸加两个黑点。第二个错误是**只读书面资料**：
百度百科写「浅棕色皮毛」（那是在描述真实水豚这个物种），
但 IP 的实际视觉设计是**明亮橙黄**。

**教训：设计一个 IP，必须先看它的实际形象，而不是读它的文字介绍。**

### 1.1 事实（来自百度百科 + 真实素材核对）

| 项 | 内容 |
|---|---|
| 来源 | 中国动画片《平头哥》少年篇的角色，原型是**水豚（卡皮巴拉）** |
| 性别 | **噜噜是雄性**（男，2024-03-21 生，狮子座，B 型血，约 15kg / 40cm） |
| 关系 | **噜噜与噜妹是一对情侣**（双 CP 人设） |
| 配色 | **明亮橙黄**（3D 渲染），噜噜是**橙黄**、噜妹是**粉色** —— 这是最关键的一处 |
| 造型 | **身体与头连成一个圆润的柱形/芒果形**（不是头身分明的大头娃娃）；脸在下半部凸出一个**方圆的吻部** |
| 眼睛 | **两点针尖大小的黑色小眼**（3D 里略带一点眼白反光，但整体仍是「小豆眼」） |
| 嘴 | **圆形撅起的小嘴**（不是咧嘴漏齿笑 —— 这是 v1 的第二个造型错误） |
| 耳朵 | **头顶两侧两只小圆耳**（像两个小圆球，位置很高，在头顶而不是脸侧） |
| 标志 | **头顶一颗小橘子**（噜噜）/ 一朵小花或蝴蝶结（噜妹）；比例极 Q，头大身短 |
| 四肢 | **短小的四只小短腿**，圆润的爪子 |
| 材质 | 毛绒质感（fuzzy / plush），有柔和的次表面散射感 |
| 性格 | **佛系淡定**、慢条斯理、情绪极其稳定 |
| 爱好 | **泡温泉**、**吃橘子** |
| 座右铭 | **「活着挺好，死了也行」** |
| 口头禅 | **「没事就是呗」** |
| 精神内核 | **「不焦虑、爱自己」**；代表「松弛感」「情绪稳定」 |

### 1.2 内核一句话

> **噜噜和噜妹是一对情绪稳定的情侣水豚。
> 它们不贩卖焦虑，只是安静地陪着你 —— 天塌下来也先泡个澡、吃个橘子。**

### 1.3 由此推导的设计原则

1. **必须是「一对」** —— 任何时候出现噜噜，就应当考虑噜妹在不在。
   孤独的单个角色违背了「陪伴式共情」这个立身之本。
2. **松弛 > 可爱** —— 不追求「萌到尖叫」，而是「看着就放松」。
   姿态要懒、要慢、要「无所谓」，**禁止**任何紧张、兴奋、尖锐的形态。
3. **橙黄是主色，不是棕也不是粉** —— 这是 IP 的实际颜色，也是识别度的来源。
   粉色作为噜妹的**伴侣色**出现，不作为全站主色。
4. **标志性元素必须准确** —— 头顶橘子、小圆耳、针尖豆眼、圆撅嘴、短腿、毛绒质感。

## 二、视觉策略：Snug Simple（温暖舒适风）

2026 年主流趋势中，与本项目内核最契合的是 **Snug Simple**：
> 柔和中性底 + 马卡龙色块 + 大圆角 + 粗圆字体 + 轻纹理 + 暖色调阴影。

与噜噜「陪伴式」的内核完全同频，故选为主策略。

### 2.1 历史错误记录（都别再犯）

| # | 版本 | 错误 | 为什么错 |
|---|---|---|---|
| 1 | v0 | **整屏粉红** | 粉色是「甜美」不是「松弛」；单一色相毫无层次。 |
| 2 | v0 | **吉祥物是粉色圆脸 + 两个黑点** | 不像水豚、不是情侣、丢掉全部识别特征。 |
| 3 | v0 | **右上角彩色 emoji 图标** | 无统一风格，是「凑功能」而非「做设计」。 |
| 4 | v0 | **缺少「一对」** | 违背 §1.3 原则 1。 |
| 5 | v1 | **用写实棕色画水豚** | 读了「浅棕色皮毛」就照着画 —— 但 IP 实际是**明亮橙黄 3D 形象**。 |
| 6 | v1 | **头身分明 + 咧嘴漏齿笑** | 真实形象是**身头一体的柱形 + 圆形撅嘴**，不是大头娃娃。 |

### 2.2 色彩系统（v2 · 基于真实 IP）

**主色 = 噜噜橙**（取自 IP 本身的橙黄），**辅色 = 噜妹粉**：

```
暖纸底     #FDF9F2   奶油米白（暖中性，不用纯白）
纸底加深   #F8F0E2
卡片       #FFFDF8   微微偏暖的白
主文字     #2F2620   暖黑（不用纯黑 #000）
次文字     #6D5F50   暖褐灰
淡文字     #A1937F

主强调     #E8912F   噜噜橙 —— 品牌主色
强调浅     #F6B95C   奶油黄（橘子黄）
强调衬底   #FDF0DA   极淡的橘

伴侣色      #F7A8B8   噜妹粉（只在噜妹身上 / 极小的提示位出现）
辅助色      #9DBFA4   温润草绿（点缀，来自它吃草的意象）
```

**配色纪律（写进代码注释）**：
- 任何一屏，**橙黄占主导**，绿做点缀，粉只属于噜妹。
- 所有阴影用**暖调 rgba**（如 `rgba(92,72,48,.08)`），**禁止纯黑阴影**。

### 2.3 形状与材质

- **圆角**：主卡片 `24px`，按钮 `999px`（胶囊），小控件 `14px`。圆角是「松弛感」的几何表达。
- **阴影**：多层、低透明、大扩散，像纸张轻轻浮起。
- **材质**：背景加**极淡的纸纹**（`< 6%` 不透明度的小 tiled 纹理），不要全屏大图。

## 三、吉祥物规范（核心交付物）

### 3.0 素材来源（v2 起实行）

**不再手绘 SVG 猜形象。** 全部使用**真实 IP 素材**（下载并本地化）：

- 来源：公开表情包站 / 壁纸站的「水豚噜噜」高清图
- 存放：`app/static/img/lumei/`（本地化，离线可用，不热链）
- 加工：由 `tools/build_assets.py` 统一裁切、去背景、压缩、生成各尺寸
- 使用：**各种状态的图**分别用在不同位置（首页 / 空状态 / 加载 / 错误 / 图标）

> 手绘 SVG 仅保留「品牌标记（favicon / 顶栏 logo）」这一类**极小尺寸**用途 ——
> 因为 16–26px 下真实图片会糊成一团。其余全部用真实素材。

### 3.1 噜噜的必画特征（手绘 SVG 时的判据）

```
1. 配色    明亮橙黄（#F2A93B 主 / #FFD88A 高光）
2. 造型    身体与头连成的圆润柱形；脸在下半部凸出方圆吻部
3. 耳朵    头顶两侧两只小圆球耳（位置高，不在脸侧）
4. 眼睛    针尖大小的黑色小豆眼（不是大眼萌）
5. 嘴      圆形撅起的小嘴（不是咧嘴笑）
6. 四肢    短小的四只小短腿
7. 常驻物  头顶一颗小橘子 ← 强识别
8. 材质    毛绒质感（fuzzy）
```

### 3.2 噜妹（雌性 · 伴侣）

同款体型，**三处差异**（一眼能分辨，但仍是同一物种）：

```
1. 整体配色  粉色（不是腮红，是整只都粉）
2. 头顶      一朵小花 / 蝴蝶结（替代噜噜的橘子）
3. 睫毛      眼睛上方加两道短睫毛
```

### 3.3 使用规则

- **必须成对出现**的场合：首页 Hero、空状态、加载中、错误页。（品牌承诺是「陪伴」）
- **可以单独出现**的场合：头像位、小图标、空间不足时。
- **禁止**：做成「兴奋/惊讶/张牙舞爪」的表情。它不会。

### 3.4 选格规则（v3 补，最重要的四条）

素材是「同一集动画的截图拼图」（5 张 sheet，每张 6×4 或 6×6 格）。选哪一格，决定成败。
**四条判据，第 4 条是后补的，也是踩坑最多的一条：**

```
1. 主体大、居中、正脸或清晰侧脸
2. 场景干净，不要挤满道具，**不能带表情包文字**（那是梗图，不适合当装饰）
3. 情绪对得上用途 —— 见 §3.5 的对照表
4. ⚠ 同一个视觉组合里的几张，必须来自**同一张 sheet 的同一行**
```

**第 4 条为什么最重要**：同一行 = 同一个场景 = 同样的光照、色温、白平衡。
跨行/跨 sheet 拼两张，不管单独多好看，放一起就是「两个来源的图」。

> **历史事故（首页 Hero）**：v2 用的是 `sheet_a[0,0]`（噜噜，冷蓝灰背景）
> + `sheet_c[2,2]`（噜妹，粉白背景）。单看每张都行，并排后 ——
> 一冷一暖、一亮一暗，**像临时拼的**。
> 量化证据：两张的 R−B（色温指标）差了 **67**，亮度差了 **25 级**。
>
> v3 改用 **`sheet_b[2,2]` + `sheet_b[3,2]`** —— 同一行的同一场景：
> 暖橙、同光照、同背景色调，而且左图是噜噜（无装饰）、右图戴粉蝴蝶结是噜妹，
> **正好对应「一对情侣」的视觉分工**。这是全素材库里唯一这样天然成对的组合。
> 色温差 67→14，亮度差 25→10（靠 §3.6 的色温归一进一步压平）。

### 3.5 状态 → 情绪对照表（选格的验收标准）

**这一条是防「望文生义」的机器化表达。** 换素材的人得先回答
「新图传达这个情绪吗」，而不是「新图好看吗」。

| 槽位 | 必须传达 | 踩过的坑 |
|---|---|---|
| `hero_lulu` | 平静、正面、**无负面情绪** | 曾用撇嘴不高兴的图当门面 |
| `hero_lumei` | 平静、正面、与 hero_lulu 同光照 | 曾与 hero_lulu 一冷一暖 |
| `empty_sleep` | 松弛、闭眼（睡得香） | 曾用「躺床上刷手机 + 好难啊」——那是焦虑 |
| `empty_wait` | 期待、等人 | —— |
| `empty_lonely` | 安静、望向远处 | —— |
| `loading_drink` | 松弛、放松（不着急） | **曾用脸挂泪痕的图** —— 加载态在哭等于说"出事了" |
| `loading_read` | 专注、在看东西 | 曾用"一只躺着 + 一只拿锅铲"，跟"在找书"毫无关系 |
| `error_confused` | 茫然、张嘴 | —— |
| `error_sad` | 低落、疲惫 | —— |
| `read_pair` | 亲密、成对 | —— |
| `read_eat` | 温暖、有食感 | 曾用"拿锅铲砸东西"——语义是生气不是吃 |

这张表在 `tools/test_art.py` 的 `MOOD` 字典里有一份**机器可读的副本** ——
新增槽位时必须同时回答"它要传达什么情绪"，否则测试报错。

### 3.6 色温归一（`tone_match()`）

「同一 sheet 同一行」能保证**场景**一致，但保不住**取景**一致 ——
取景偏下就多进暗部，取景偏上就多进高光，两张并排立刻一明一暗。

实测 Hero：噜噜亮度 162.8 / 噜妹 137.8，**差 25 级**。
试了 4 档 focus 都拉不动（差异来自素材本身，不是取景），
所以用 `tone_match()` 做线性映射对齐（Reinhard 色彩迁移的简化版）。

- **强度 0.7** 而不是 1.0：完全对齐会把主体本身的固有色也洗掉
- **只对同一组图做**（`TONE_PAIRS` 里登记），不全局统一 ——
  每张图有自己要传达的情绪，「星空暗调」「黄昏暖调」是刻意的氛围，拉平就没了
- 构建末尾会**自动量一遍** Δ色温 / Δ亮度，超容差告警

### 3.7 残影修补（`repair_corner()`）

这些素材除了底部文字水印，**部分格子的四角还压着一个半透明的圆形 logo 残影**
（转发水印）。它很淡，缩略图完全看不出，一放大就在纯色背景上显形。

处理方式：对指定的角做**内容感知填充** —— 用同一条带上的邻近像素向角部拉伸，
再与原因做羽化混合。

> **为什么不直接模糊**：模糊会留下一团「糊斑」，比原来的残影更显眼；
> 拉伸邻近背景能接上原有的渐变，看起来才像「本来就没有」。

**按需开**（`REPAIR` 表），不全局默认 —— 对干净图做无谓修补只会引入新伪影。

## 四、全站适配（v2 的核心要求）

> **主题不是一张首页皮肤，是一套贯穿全站的语言。**
> 任何页面「丢主题」都算没做完。

### 4.1 必须适配主题的页面清单

| 页面 / 区域 | 主题表达方式 |
|---|---|
| 首页 Hero | 一对吉祥物 + 手写体口头禅 + 暖色光晕背景 |
| 搜索框 | 圆形焦点光晕、橘子色强调 |
| 书籍卡片 | 圆角 + 暖阴影 + 封面配色走主题色系 |
| 来源抽屉 | 圆角行、暖色状态点 |
| **阅读页** | **独立的噜妹阅读配色**（奶油底 + 暖橘高亮），页眉页脚有橘子色细节 |
| **阅读设置面板** | 配色选择器里含「噜妹」色卡 |
| 书架 | 卡片暖阴影、进度条走主题渐变 |
| 文件 / 导出 | 图标用主题色、格式标签统一 |
| **空状态** | 每处空状态配对应情绪的吉祥物图 |
| **加载中** | 用噜噜的「等待」状态图，而不是三点动画 |
| **错误页** | 用噜噜的「发呆/懵」状态图 + 口头禅安慰 |
| Toast / 弹窗 | 圆角 + 暖色 + 轻微动效 |
| 移动端 tabbar | 图标统一、主题色高亮 |

### 4.1b 落点验收（v3 补：`test_motion.py` 的 `THEME_COVERAGE` 表）

§4.1 是"该适配什么"的愿望清单；下面这张表是**机器可验的契约** ——
每个条目对应 `lumei.css` 里的一段选择器，缺了就红。

| 页面 / 组件 | 主题手法 | 为什么这样 |
|---|---|---|
| 书架 · 进度条 | 在读进度用噜噜橙渐变 | 内容区里**唯一该有色**的东西：它表示"你花了时间" |
| 书架 · 书封高光 | 把已有的冷白高光调暖 | ⚠ 别新写 `::after`，会和 `app.css` 那条打架 |
| 书架 · 继续阅读按钮 | 加实心橙阴影 | 书架里最常点的按钮，配最实的色 |
| 文件行 · 图标 | 暖色底衬（不改 emoji） | 与整站同色温即可，emoji 替换是另一个任务 |
| 抽屉 · 头部 | 2px 暖色下边线 | 是**最小记号**：用户来办事时大色块会碍事 |
| 抽屉 · 移动端把手 | 暖色 | 同一条视觉语言 |
| 遮罩 | 暖调 rgba（非冷灰） | 冷灰盖上去会让整站"突然变凉" |
| 任务卡 | 左侧暖色边线 | 像"噜噜在替你跑腿" |
| 任务卡 · 运行中 | 左边线**轻微呼吸** | ⚠ **只对 `.is-running`**：已完成的还在呼吸=骗人 |
| 来源卡 | 只改 hover 描边 | ⚠ **状态色（ok/warn/bad）不能动** —— 那是语义 |
| 榜单标签 | 选中态走暖色浅底 | 原黑底白字太"冷" |
| 确认框 | 顶部 2px 暖线 | 用户在**做决定**（尤其危险操作），可爱化会弱化"有后果"的信号 |
| 令牌闸门 | 顶线 + `empty_wait` 插画 | 公网首屏 = 品牌第一印象，值得放插画 |
| 书名确认卡 | 左侧暖色竖线 | 与任务卡同族：这是"要你拿主意的一件事" |
| 阅读页 | 章末收尾 + 色卡角标 | 见 §5 |
| 首页 / 空状态 | 吉祥物 + 插图 | 见 §2.1 |

**反向约束（同样机器可验）**：`app.css` / `reader.css` / `motion.css` /
`backgrounds.css` 里**不许出现 `data-theme="lumei"`** ——
品牌规则必须集中在 `lumei.css`，否则"删掉一个文件就能回中性"的可摘性就没了。

**第三条反向约束（v3.1 补）**：**组件的骨架样式不许写行内 `style`** ——
行内优先级高于任何类选择器，主题层永远够不到它。`confirmBox` / 令牌闸门
/ 书名确认卡就栽在这上面（整块弹窗无法被主题化，也写不了 `reduce` 兜底）。
`test_motion.py` 现在会扫 JS 里的组件骨架行内样式，命中就红。

### 4.2 背景（`backgrounds.css`）

**不要**满屏飘「噜」字。改为**氛围层**：

1. **暖色光晕**：2–3 个大而模糊的暖色圆斑，缓慢漂移（`48s+` 周期，慢 = 松弛）。
2. **极淡纸纹**：`< 6%` 不透明度的小 tiled 纹理。
3. **偶发元素**：极少量、极慢的橘子/叶子剪影飘过（`> 45s` 一个，`pointer-events:none`）。

### 4.3 交互微动效

> **v3 更新**：动效不再是"各处自己写一点"，而是收进**独立的动效层**
> （`css/motion.css` + `js/motion.js`）。原因是实测发现同一个界面里
> 有的顺、有的顿 —— 三条曲线、四种时长散在六个文件里，改节奏要全局找。
>
> 动效层是**中性**的（不含任何噜妹元素），删掉它站点只是变朴素，不会坏。
> 品牌层只负责"噜妹该怎么动"（浮动幅度、漂浮物），不定义基础曲线。

**分层职责**

| 层 | 文件 | 管什么 |
|---|---|---|
| 令牌 | `tokens.css` | `--dur-*` / `--ease*`（历史遗留，逐步并入 `--mo-*`） |
| 动效 | `motion.css` | `--mo-*` 令牌、涟漪、错峰、入场、状态连续性 |
| 动效编排 | `motion.js` | 什么时候动：错峰注入、视口触发、主题过渡开关 |
| 品牌动效 | `lumei.css` | 噜妹专属：呼吸浮动、极慢漂浮物、章末收尾标记 |

**三条纪律**

1. **点到即反馈** —— 按压位移 ≤ 3px、时长 ≤ 170ms，挂在 `pointerdown` 上不等 `click`。
2. **位分分层** —— 容器走得少（8px）、主元素走得多（14px）；背景动得慢、卡片动得快。
3. **尊重 `prefers-reduced-motion`** —— CSS 与 JS 两侧都必须读，这是可访问性要求。

**具体规则**

- 按钮 hover：`translateY(-1px)` + 阴影加深，`170ms`。**不要**缩放抖动。
- 卡片 hover：阴影加深 + 边界微亮，`280ms`。
- 卡片入场：`translateY(14px)` + 淡入，`460ms`，错峰步长 `38ms`，**上限 12 个**。
- 列表项按下：**不缩放**（整行缩放像抖动），改为压暗背景。
- 主题切换：开 280ms 色值插值 + 一次极短的亮度呼吸，切完立刻摘掉过渡类。
- 吉祥物：**呼吸式**上下浮动（`4.5s` 周期，`5px` 幅度），两只错开半周期。
  **禁止**弹跳、旋转、快速抖动。
- 加载态：**不用三点动画**，用「噜噜在翻书」+ 一行说明（三点没有信息量）。
- 错误态：用「懵」的定格表情，**不做浮动** —— 动效必须与语义一致。

### 4.4 素材落点（11 组全部要有去处）

> 素材做了不用 = 没做。`tools/test_motion.py` 会检查**每张图是否都有落点**，
> 出现孤儿素材直接报错。**下表按真实代码引用方式核对过**（v3），
> 分三类：`index.html` 直引 / `art.js` 状态映射 / `lumei.css` 背景。

| 素材 | 落点（真实页面） | 引用方式 | 注册键 |
|---|---|---|---|
| `hero_lulu` | 首页 Hero 左（噜噜） | `index.html` 直引 | `HTML_ONLY` |
| `hero_lumei` | 首页 Hero 右（噜妹，`is-lumei`） | `index.html` 直引 | `HTML_ONLY` |
| `empty_wait` | 首页「说个书名」空态（`#homeEmpty`） | `index.html` 直引 | `HTML_ONLY` |
| `empty_sleep` | 书架为空（`#shelfEmpty`） | `index.html` 直引 | `HTML_ONLY` |
| `loading_drink` | 文件页「还没导出过」（`#fileEmpty`） | `index.html` 直引 | `HTML_ONLY` |
| `empty_lonely` | 发现页「搜到但都没通过验证」 | `art.js` → `discover.js` | `ART` |
| `loading_read` | 阅读器取章节中（`busyHTML`，compact） | `art.js` → `reader.js` | `ART` |
| `error_confused` | 阅读器章节取不到 + 来源抽屉探测失败 | `art.js` → `reader.js` / `sources.js` | `ART` |
| `error_sad` | 整本打不开 / 搜到但全不通过 | `art.js` → `reader.js` / `discover.js` | `ART` |
| `read_pair` | 章末收尾标记（读完一章） | **CSS 背景**（`lumei.css` L286） | `CSS_ONLY` |
| `read_eat` | 阅读配色色卡的角标 | **CSS 背景**（`lumei.css` L300） | `CSS_ONLY` |

> ⚠ 三类引用方式的划分不是随意的：`HTML_ONLY` 的三张（Hero + 首页/书架/文件空态）
> 是**首页自己的布局**，插在静态 HTML 里、不进 `st-art` 体系；
> `CSS_ONLY` 的两张（章末 / 色卡）**不能进 `<img>`**，原因见 §4.5。
> 改素材引用方式时，这三张集合（`art.js` 的 `HTML_ONLY` / `CSS_ONLY`）要同步改。

### 4.5 为什么章末装饰必须用 CSS 背景而不是 `<img>`

分页算法（`reader.js` 的 `paginate`）靠**量每个段落的 offsetTop** 来切页。
任何会占高度的元素插进正文，都会把页码算错 —— 表现为"翻到最后一页却还有半页空"
或者"某一段被吞掉"。

背景图不参与布局，是唯一安全的选择。代价是它不能被 `alt` 描述，
但它是**纯装饰**（`alt=""` 语义等价），所以可接受。

## 五、验收清单

改完 UI 后**逐条对照**（自动化部分见 `tools/test_motion.py` / `test_motion_live.py`）：

**品牌**
- [ ] 主色是**噜噜橙**，不是粉、不是棕
- [ ] 粉色只属于**噜妹**（作为伴侣出现）
- [ ] 吉祥物用**真实 IP 素材**，不是手绘猜的
- [ ] 吉祥物是**橙黄色 + 头顶橘子 + 针尖豆眼 + 圆撅嘴**
- [ ] 首页**同时出现噜噜和噜妹**
- [ ] 阴影是**暖调** rgba，不是纯黑
- [ ] 圆角 ≥ 首页卡片 24px
- [ ] 没有满屏「噜」字漂浮
- [ ] 深色模式（黑糖噜妹）同样是暖调
- [ ] 拿远看，整体是「温暖、安静、想待着」，不是「甜腻、吵闹」

**全站适配**
- [ ] 阅读页有**独立的噜妹配色**，且是**默认**配色（不是要用户自己去选）
- [ ] 空状态 / 加载 / 错误页都有对应情绪的吉祥物图
- [ ] **11 组素材每一张都有落点**（`test_motion.py` 会检查孤儿素材）
- [ ] 书架 / 文件 / 来源抽屉 / 弹窗 / 任务卡都有主题痕迹（`test_motion.py` §6 覆盖表）
- [ ] 品牌规则**只在** `lumei.css`（业务 CSS 里搜不到 `data-theme="lumei"`）
- [ ] 阅读设置面板的配色选择器含「噜妹」色卡

**动效**
- [ ] 所有过渡走 `--mo-*` 令牌（业务 CSS 里搜不到裸 `cubic-bezier`）
- [ ] 列表错峰统一走 `stagger()`（业务 JS 里搜不到行内 `animation-delay`）
- [ ] 按压有即时反馈（涟漪 / 位移），不等网络
- [ ] 主题切换是**过渡**不是硬切，且过渡类**会摘掉**
- [ ] `prefers-reduced-motion: reduce` 下动效真的停
- [ ] 移动端小屏减少动效（省电）
