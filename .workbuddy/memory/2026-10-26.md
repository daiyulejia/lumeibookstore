# 2026-10-26 · 搜不到复盘（第六跑）

## 一句话
今天没有新的「用户搜不到」案例（10-25 的 11 次搜索全是探针，10-26 真实搜索 0 次）；
真机复现挖出两处「判据自己会说谎」，都修了并上线（`6b4e834`、`3e75739`）。

## 做了什么
1. **两字书名的确切命中太松**：`tightness` 的容差 `max(1, len(kw)//3)` 让
   「嘿兄弟」「兄弟盟」对《兄弟》判 1.0 → `rank()` 只留它们、`engine` 的收手门
   被喂饱、日志写 `确切=2`。改成 `allow = 0 if len(kw) <= 2 else max(1, len//3)`。
2. **熔断退避跨重启丢失**：`_save`/`_ensure_loaded` 只认「仍在冷却中」→ 冷却
   一到期的条目连 `streak` 一起消失，15m→30m→60m 从没生效（线上三天每次 ship
   后都倒退）。改法：到期条目也落盘（until=0）、读回进 `_memory` 失败史（不进
   `snapshot()`，不产生幽灵记录）、再挂时接上 streak 并按半开试探、`note_ok`
   清空、7 天（`FORGET_AFTER`）作废、读回打一行日志。
3. 判据：`test_relevance.py [1b]` 组（8 正 + 5 反 + rank 端到端）、
   `test_source_health.py`「冷掉的账」组 9 项；`mutate.py` 新增 tight 3 + cold 5。
4. 上线前做了风险体检：拿线上候选池对 10 个两字书名跑新旧两版 `rank()`，
   没有一个变空（脚本 `dist/tmp/tight_risk.py`）。

## 踩到的坑（值得记住）
- **反证靶点也是一种判据**：改了 `_save` 的 docstring，`[backoff] 熔断状态不落盘`
  的靶点当场脱节；新代码里 `if until <= now:` 在两处出现，另一条突变变成
  「多处命中」。ship 第一趟因此停在 [1/4]，**没有上线**（工具是对的）。
  修法：靶点挂在**行为**上，不要挂在说明文字上。
- 线上验证读取回日志：`21:46:34 熔断器读回落盘：仍冷却 0 个；已到期但保留失败史
  2 个（wikisource(streak=2), xbqg5200(streak=1)）` → 之后 wikisource 熔断
  **1 小时**、xbqg5200 **30 分钟**（旧口径都是 15 分钟）。
- 探针 `sample=1` 会顺手抽读一章，耗时（13~14s）不能当用户体感。
