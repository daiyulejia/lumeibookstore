# 项目长期记忆（novel-downloader / 噜妹书院）

## 每日搜不到复盘的硬规矩
- 线上日志优先：`~/noveldock/logs/app.log`（当天）+ `app.log.<日期>`（前一天，零点轮转）。
- 判「0 条」的两种含义必须分开：**书没有** vs **源挂了**。
  `search.done` 带 `答=/挂=/未回=/熔断=/自限=/卡满=/确切=`（10-23 四格、10-24 加确切、
  10-25 加「熔断」、11-16 加「自限」第六格）：**答+挂+未回+熔断+自限 必须等于应搜总数**，
  未回/熔断/自限都要点名。旧字段 `超=` 已删。
- ⚠ `候选=0` 不是唯一的"搜不到"。`候选=4 确切=0` 同样是搜不到（4 条撞词），
  日报必须两个一起看。只要复现能搜到，就**不进** `known-missing.md`。
- 引擎上限：扇出 20s、总预算 22s（联网兜底那轮 32s）；源自带上限统一 6s。
- **「零搜索」有两种，日志里长得一模一样**（11-15）：①服务在线、没人搜；②实例不可达、
  日志压根拉不到。①能写"没有新案例"，②只能写"**没有数据可判**"。
  开工第一件事是探可达性（22/80/443/8000 + ICMP + 境外节点），
  历史上的"连续三天没有新案例"里就藏着一次产品下线。

## 已证实的病灶（别再重犯）
- **重复的同一个请求不合并 = 自己把自己打成搜不到**（11-01）。8 秒 16 个同名同参请求各起
  一轮引擎 → 搜索引擎返回**别的页面**，8 并发 7/8 `候选=0`，单独搜 `候选=2 可读=2`。
  修法 `app/searchflight.py`（在飞合并，**不是缓存**）：收手看「还有没有订阅者」。
- **凡是"连续 N 次"的判据，都要问：这 N 次会不会是同一瞬间数出来的**（11-01、11-16）。
  ①`search_shape` 已加观测去重（180s 窗口，不是耗时阈值）；②**熔断器 `note_fail`
  和学站 `note_search_fail` 仍按次数**，仍能被一瞬间喂饱 —— **未修**；③11-16 又冒出
  第三种形态："同一件事被数 N 遍"——冷却期内每轮搜索都记一次失败（已修，见下条）。
- **判据固化了旧行为时，红的是判据不是产品**（11-01）：「连调三次触发作废」的老用例变红，
  是因为它们把旧 bug 写成了断言，得改成「三次**独立**观察」，不是把产品改回去。
- **源必须有自己的墙钟上限**。否则引擎放弃后它仍活几分钟，吃线程和连接池
  （共享 httpx 只有 10 条）。已修 wikisource 186.9s→6s、wyshu→6s。新加源先问这一句。
- **熔断器只认"跑完的失败"**：卡死的 future 永不完成 → `take_error()` 拿不到 → 永远学不会。
  墙钟到点必须清算 pending。
- **空结果 ≠ 挂**（走 `note_ok`，否则搜几本冷门书全站拉黑）；**反过来也成立**：
  源"建索引/抓页全失败"却返回 []，必须 `note_error`，别伪装成"没这本书"。
- **「本地保护」≠「远端故障」**（11-16）。`fetch_text` 在同域冷却期内直接抛错、一个请求
  都不发 —— 那是我方保护，不是站挂了。引擎把它当失败喂熔断器 → 冷却 120s 却熔断 300s
  → streak+1 → 10/20/40 分钟封顶 8h：**越保护越死**。凡"我们自己决定不做的动作"
  （限流冷却 / 熔断跳过 / 预算收手）都必须与"对方坏了"分开归因、分开记账，
  否则日报写"这个站坏了"，处置却是"降速等它"，正好相反。已加 `errors.LocalCooldown`
  + `search.done` 第六格 `自限=`，两个入口（抛异常 / `take_error()` 交回字符串）都要判。
- **调度算术要按「批数」算，只算单类等于没算**（11-16）。榜单注释写"最坏 12.8s < 25s"，
  而 7 类 / 3 并发 = 3 批 → 38.4s ≫ 25s，**必然少一类**且不报错。凡"每批最多 X 秒"
  的设计，先问一共几批；判据写成 `批数 × 单类最坏 ≤ 预算`（纯常量关系，不碰耗时）。
- **「够多」≠「够好」**（10-24）。收手看「候选条数/答的源数」会被噪声骗，必须有确切命中门。
  "有没有结果"与"是不是这本书"是两件事，凡用户能感知的差异，日志里必须有字段。
- **埋点要埋在人看得见的那批对象上**（10-25）。`确切` 曾取扇出循环的累加值，而联网兜底
  交回的候选不过那个循环 → "救回来了"被记成 `确切=0`。凡"候选=1、确切=0"这种
  **算术上不成立**的行，先怀疑口径，别怀疑书。
- **「声明的时间预算」比调用方的收手点长，等于没声明**（11-09）。`RegistrySource` 内部 7.0s，
  而引擎软截止 6.0s、常态收手点才 3.5~4.5s → 30 个站的产出 12/17 次被整批扔掉，
  它却"账本自洽"。凡"我内部要跑 N 秒"的组件，先问调用方肯等几秒；凡"账本加起来对"的复盘，
  再问一句「这个源没答，是它慢还是我们不要它了」。
- **httpx 的 `timeout` 是分操作的，不是墙钟**（11-09）。`www.taiminc.com` 给了 3.5s 却跑
  7.3s（慢速吐字节），"已设超时" ≠ "有上限"。
- **「预算是承诺，不是墙钟」，隐藏入口至少还有两个**（11-15）：①**退避睡眠**不认表
  （wikisource 请求超时夹过了，但睡完不看表 → 声明 6s 实测 7.33s）；②分操作超时相加
  （wyshu 声明 6s 实测 10.2s）。查"预算有没有牙"要顺着**每一处 `sleep` 和每一次发请求**看。
- **自建索引型来源在"调用方 1.5s 就收手"下会 100% 白跑**（11-15）。冷 → 建索引 4.25s →
  被 1.5s 扔 → `complete=False` 不落盘（10-24 定的规矩）→ 永远冷，还每轮吃一个线程。
  修法不是加预算、也不是声明 `budget_s` 让引擎等（命中率 2/12），而是**搜索只读缓存、
  冷的把构建踢到后台**（单飞 + 重试间隔）。
- **被跳过的对象也要进分母**（10-25）。熔断跳过的不进账，"全部源都在熔断"就成 `答=0/0`。
  已加「熔断=N(名字)」格 + 全灭时明写一行。
- **「先查状态、后动手」中间隔着一次 await，就是一道缝**（11-04）。`acquire()` 在处理函数里跑，
  `subscribe()` 要等生成器第一次 `__anext__()`；老请求在这道缝里断开 → 新一轮挂到**弃轮**上 →
  引擎立刻收手 → 用户 1.5s 拿到 `候选=0`。修法不是加判断，是把「拿一轮」和「挂上去」
  收进同一把锁（`FlightBook.subscribe`）。`aborted=True` 也≠用户走了：**先看 `合并=N`**。
- **防呆 UI 不许在操作跑起来之后再打断它**（11-02：确认框在搜索 1.3s 时盖上来，
  一点就 abort 重来，13 次搜索 10 次是同名第二发）。
- **容差不能有"下限保底"**（10-26）。`tightness` 的 `max(1, len(kw)//3)` 让两字书名也吃
  「多一个字」的容差 → 「嘿兄弟」成《兄弟》的确切命中、日志写 `确切=2`。两字必须零容差。
- **「有几个入口」要按「共同点」grep，不是按上次改过的符号**（11-17）。11-16 修「自限流不是
  源故障」时 grep 的是 `note_fail`（熔断器），于是只改了 engine/ranks；而这批入口的共同点是
  `classify_fetch_error`（**6 处**各手写一遍 `slow=…; why=FAIL_SLOW if slow else FAIL_DOWN`）
  —— 换个词 grep 就看得到。已收敛成 `registry.site_fault_why()`/`note_fetch_fail()`，
  并加 **AST 闸门**（`test_site_fault` ⑨：`classify_fetch_error(` 只许一个调用点，
  且扫描器要自证"确实扫到那 1 次"，否则判据恒真）。
- **健康判据只有死亡线、没有复活通道 = 资产单向缩水**（11-17）。越线（`down > 2*ok`）后同时被
  `searchable_sites()` 和 `discovery._verify` 排除 → 永远拿不到下一次 ok → 计数**冻结在
  `down == 2*ok+1`**（库里 4/4 个模板站全停在这个值上，就是指纹）。已加 `probation_sites()`
  试用通道（每次 2 个 / 每站 6h / 一次成功即复活 / **不计入** `sites_searchable`）。
  凡"只进不出"的判据，先问一句**它怎么回来**。
- **「学会了」不等于「这个站行了」**（11-06）。`save_search_tpl()` 清 `search_fail`，而
  `should_try_learn()` 拿它当放弃门槛 → 门槛永远够不到 → 5 个站每天「学会→判死→再学」6 天。
  **模板账 ≠ 站账**（站级 `tpl_dead` 跨模板累计 + 7 天冷却）。放弃门槛读的计数，先问**谁清零它**。
- **闸门装在一个入口上，就等于没装**（11-11）。11-06 的 `tpl_dead` 只让
  `note_search_result()` 记，漏了**复核判假**那条：`clear_search_tpl()` 只 +`search_fail`
  → 下一轮又被清零 → hgcha 一夜 3 轮 × 3 夜，`tpl_dead` 那个键**从没被创建过**。
  立判据前先数一遍"这件事有几个入口"：谁清模板、谁清计数、**谁删站**。
  删站/删书也是全局状态变更，必须**点名**落日志（`health_check` 原来零字段）。
- **别为"可搜源 N 个"高兴**（11-06）。29 个里对《三体》只有 **5 个**真给出含关键词的书
  （15 个抽不出、9 个清单是推荐位）。准入该问「控制实验里抽出过几条」：
  `tools/probe_pool_health.py`，**必须在服务器上跑**（本机 DNS 解析不了这些站）。
- **「有结果」≠「有能读的结果」**（10-27）。死链也能是确切命中（tight=1.0/score=100）：
  唯一候选 0 章，收手门被它喂饱 → 「本地一条可读都没有、出去找」一次都进不去。
- **「某个站 0 产出」先问是不是我们自己的问题**（10-30）。三种病因：①站里没这本书
  ②我们打太快被限速（杰奇 CMS 30 秒一次）③模板真坏。只有③该判死，①②命中时**不碰** shape。
- **判据只认一种文体，就等于只服务一种书**（10-31）。`toc_quality` 只认「URL 单调 + 第N章」，
  散文集目录叫「自序」「第一辑 阿勒泰文字…」→ 三天三本冷门书全栽。第三条证据要取自
  **页面自己的说法**：有「章节列表」+ 链接都挂在本页这本书下 + 是主要链接群。
- **一次搜索会改全局状态时，必须把变化打进这次搜索的日志**（10-30）。源池 22→15 曾经
  零字段，只能事后 diff `registry.json` 才发现。已加 `源池=A→B`。取不到打 `?`，不补 0。
- **写完 ≠ 上线**（10-30）。判"上线了"只看两条：服务重启时间晚于提交时间、md5 与本地一致。
- **测试要自带数据，别靠环境**（10-30）。本机 `cache/registry.json` 的 searchable 是 0，
  于是"两头相等"恒真，反证当场报"存活 2 条"。凡断言里的数字来自环境，先伪造它。
- **测试只走一条开关组合 = 另一条完全没覆盖**（10-27/10-31）。`test_discover_fallback` 全用
  `probe=False` → "联网→探测"从没跑过；给 `stats` 加 `web_verify` 时在 preempt 分支读了
  一个只在串行分支赋值的变量 → 线上 500。加字段先问：这条链上**每个分支**都给过它值吗？
  ⚠ 同进程测试共享熔断器：新场景必须用**独立源名**（`hang8`），否则被前面场景拉黑、源压根
  不挂 → 测试"绿的是空转"。
- **反证靶点是判据本身的一部分**（10-24/10-26/11-18 栽三次）。改收手/超时/记账那几行前，
  先 `grep` 一下它是不是突变靶点；靶点文本**从源码复制**，别凭印象写缩进。
  同一语句出现两处会「多处命中」。`test_ship_chain` 会在第 1 分钟抓住脱节 —— 别跳过它。
- **「有书链接」≠「这是搜索页」**（11-18）。`raw>0 且 hits=0` 一律记 `FAIL_EMPTY` 会把
  「站里没这本书」和「模板根本不认关键词」合成一笔，而处置相反（补书 vs 作废重学）。
  后者 `raw>0` 恒成立 → 永不记 `shape` → 模板永不作废 → 每 6h 被试用通道白打一次、出不去。
  判据：换个肯定没人写过的词再问，**控制词也抽回真词 80% 以上的一屏** = 不认词
  （实测 ldxs1 65/62 条 vs 真站 tadu/384g 88/0、100/0）。只对 `search_hit==0` 的站做，
  判中三次即作废 → 成本自终止；打不通一律"没结论"，不许当判假。
- **现成工具会在他最该用的场景里主动弃权**（11-18）。`sitelearn.judge_by_control`
  开头就 `if not hits: return "unknown"`，而"不认关键词"的站恰恰永远 `hits==0`。
  复用老判据前先读它的**提前返回**，那才是它服务的病型边界。
- **"查询"接口也可能是写操作**（11-18）。`probation_sites()` 挑中即落 `probation_at` 并写盘：
  一次只想打印"下次会挑谁"的审计，就把两个站的 6 小时名额消耗光了。问状态前先看它改不改状态。
- **判据不许赌"异步还没开始"**（11-15）。断言"后台没抓取"时，后台线程可能已经抓了 ——
  同一份代码第一遍绿、第二遍红。"这条**同步路径**有没有副作用"要用只记账的桩来问，
  异步那半单独一组验。**假时钟必须自己推进时间**（`time()` 走虚拟钟），
  否则"预算用完"永远不来，判据报红**而产品是对的**。

## 工具与环境的坑
- **Windows 上「管道/重定向」= GBK，而 Linux 永远复现不出来**（11-13）。启动横幅里的
  `⇄`（还有 `⚠ ✓ ✗ ✅ ❌`，`→ ·` 没问题）在 cp936 里没有 → `print()` 直接抛
  UnicodeEncodeError → 进程在 `uvicorn.run()` **之前**就退，守护脚本每 60 秒再拉一次，
  一上午 542 次。修法不是删字符，是**加固 stdio**：只放宽 `errors`、编码得了的流一个字节不动
  （全量 replace 会把真错误静默变成 `?`）。凡"只在某个平台/某种 stdio 下才炸"的 bug，
  判据必须自己**构造那个环境**（`PYTHONIOENCODING=gbk` / `open(encoding="gbk")`）。
- **真机套件用 `--no-check` 起服务 = 唯一会崩的那条分支从来没被走过**（11-13）。
  两问：① 我的测试是不是恰好绕过了出问题的那条路？② 失败时，报错里有没有原因？
  （`LocalServer` 原来 `stderr=DEVNULL`，崩了只报"端口 N"，原因全被扔掉。）
- **有测试 ≠ 有保护：判据必须登记进 ship 的清单**（11-15）。`tools/test_sched.py`
  312 行、断言也不差，却**从没进过 `STATIC_SUITES`** → 每天都不跑，等于零保护。
  听到"我们早就有判据了"，先 `grep <文件名> tools/ship.py tools/mutate.py`。
  ⚠ 同母题的另一种：**账只在返回值里，日志/状态接口里没有** —— 定时任务直接调
  `ranks.refresh()`（不走有埋点的 HTTP 入口），`pending` 就被丢了，
  日志写「成功 6 / 失败 0」而事实是某一类这轮没更新（11-15）。
- **「默认超时」是隐形的墙钟，要和外层预算对比着看**（11-15）。`fetch_text` 默认
  25s，而榜单整轮预算也是 25s → 一个慢源必然吃掉整轮，代价是"某一类停更一轮"。
  查法：逐个 `fetch_text(` 调用点问"上面有没有 `fast_mode` / 预算"，并量出正常耗时
  再定上限（榜单正常 0.2~2.4s → 给 6s）。
- **「主机级不可达」≠「产品挂了」**（11-13）。产品崩了端口给 `refused`（有回包）；
  连拒绝都没有、四个端口一致全超时、ICMP 也不回 → 实例不在线/安全组/路由。
  自证不是自己网络：拿境外多节点（check-host.net）打同一个端口。别报"线上挂了"就完事，
  要说清是"主机不见"还是"进程不见"。
- **开工先 `git status`**（11-13）。工作区里躺着没还原的突变注入
  （`app/engine.py` 的 `tight_streamed` 被改成 `streamed`，正是 `mutate.py 召回` 第 5 条）——
  在脏树上跑 ship 等于拿被破坏的代码上线。
- `env -u http_proxy … python -c "多行"` 在本机 Git Bash 下静默无输出 → 用 `unset … ; python …` 或写文件。
  **`ssh` 同样中招**：`env -u … ssh … 'cmd'` 返回空且 exit=0，看起来像"服务器没日志"。ssh 直接打。
- 本机 `curl` 打线上返回空（连 `-w` 都不打印）→ 用 `.venv/Scripts/python.exe` + urllib。
- `tools/mutate.py` 与 `tools/ship.py` **不能并发**；看到"测试期间源码被外部改动"先查别的会话。
