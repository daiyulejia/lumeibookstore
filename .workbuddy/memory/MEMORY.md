# 项目长期记忆（novel-downloader / 噜妹书院）

## 每日搜不到复盘的硬规矩
- 线上日志优先：`~/noveldock/logs/app.log`（当天）+ `app.log.<日期>`（前一天，零点轮转）。
- 判「0 条」的两种含义必须分开：**书没有** vs **源挂了**。
  `search.done` 带 `答=/挂=/未回=/熔断=/卡满=/确切=`（10-23 四格、10-24 加确切、
  10-25 加「熔断」第五格）：**答+挂+未回+熔断 必须等于应搜总数**，未回/熔断后都要点名。
  旧字段 `超=` 已删。
- ⚠ `候选=0` 不是唯一的"搜不到"。`候选=4 确切=0` 同样是搜不到（4 条撞词），
  日报必须两个一起看。只要复现能搜到，就**不进** `known-missing.md`。
- 引擎上限：扇出 20s、总预算 22s（联网兜底那轮 32s）；源自带上限统一 6s。

## 已证实的病灶（别再重犯）
- **重复的同一个请求不合并 = 自己把自己打成搜不到**（11-01）。8 秒 16 个同名同参请求
  各起一轮引擎 → 搜索引擎返回**别的页面**（候选是「江苏教育考试院」「3D 漫画」），
  8 并发 7/8 `候选=0`，而单独搜 `候选=2 可读=2`。修法 `app/searchflight.py`（在飞合并，
  **不是缓存**）：收手判据必须是「还有没有订阅者」，不是「这个请求还在不在」。
- **凡是"连续 N 次"的判据，都要问：这 N 次会不会是同一瞬间数出来的**（11-01）。
  同一场风暴还给 4 个站各投了 3 票「不是搜索页」→ 模板永久作废、源池 23→19。
  加的是**观测去重**（180s 窗口），不是耗时阈值。同类未修：熔断器 `note_fail`、
  学站 `note_search_fail` —— 它们也按次数，也能被一瞬间喂饱。
- **判据固化了旧行为时，红的是判据不是产品**（11-01）。加去重窗口后，一批
  「连调三次触发作废」的老用例全红 —— 那是它们把旧 bug 写成了断言，得改成
  「三次**独立**观察」（先把上次时间戳推远），不是把产品改回去。
- **源必须有自己的墙钟上限**。否则引擎放弃后它仍活几分钟，吃线程和连接池
  （共享 httpx 只有 10 条）。已修 wikisource 186.9s→6s、wyshu→6s。新加源先问这一句。
- **熔断器只认"跑完的失败"**：卡死的 future 永不完成 → `take_error()` 拿不到 → 永远学不会。
  墙钟到点必须清算 pending。
- **空结果 ≠ 挂**（走 `note_ok`，否则搜几本冷门书全站拉黑）；**反过来也成立**：
  源"建索引/抓页全失败"却返回 []，必须 `note_error`，别伪装成"没这本书"。
- **「够多」≠「够好」**（10-24）。收手看「候选条数/答的源数」会被噪声骗。必须有确切命中门。
  **"有没有结果"与"是不是这本书"是两件事**：`候选=4` 同形对应"有正主"和"4 条撞词" ——
  不是判据太松，是没埋点。凡是用户能感知的差异，日志里必须有字段。
- **埋点要埋在人看得见的那批对象上**（10-25）。`确切` 曾取扇出循环的累加值，而联网兜底
  交回的候选不过那个循环 → "救回来了"被记成 `确切=0`。凡"候选=1、确切=0"这种**算术上不成立**
  的行，先怀疑口径，别怀疑书。
- **「声明的时间预算」比调用方的收手点长，等于没声明**（11-09）。`RegistrySource` 内部 7.0s，
  而引擎软截止 6.0s、常态收手点（确切命中+已答2源+宽限 3.5s）才 3.5~4.5s → 30 个站的产出
  12/17 次被整批扔掉，它却"账本自洽"（答+未回=总数）。三件一起修才有用：预算 7.0→5.0、
  源用 `budget_s` 声明让 ②③ 让路、**连接池 10→32**（30 站压 3 批串行 = 它要 7s 的直接原因）。
  凡"我内部要跑 N 秒"的组件，先问调用方肯等几秒；凡"账本加起来对"的复盘，再问一句
  「这个源没答，是它慢还是我们不要它了」。
- **httpx 的 `timeout` 是分操作的，不是墙钟**（11-09）。`www.taiminc.com` 给了 3.5s 超时却
  跑了 7.3s（慢速吐字节），"已设超时"不等于"有上限"。
- **被跳过的对象也要进分母**（10-25）。熔断跳过的不进账，"全部源都在熔断"就成 `答=0/0`：
  加得起来、零信息，和"搜遍了都没有"一模一样。已加「熔断=N(名字)」格 + 全灭时明写一行。
- **「先查状态、后动手」中间隔着一次 await，就是一道缝**（11-04）。`acquire()` 在处理函数里跑，
  `subscribe()` 要等生成器第一次 `__anext__()`；老请求在这道缝里断开 → 新一轮挂到**弃轮**上 →
  引擎立刻收手 → 用户 1.5s 拿到 `候选=0`，日志写「客户端已断开 合并=2」。修法不是加判断，
  是把「拿一轮」和「挂上去」收进同一把锁（`FlightBook.subscribe`）。
- **`aborted=True` ≠ 用户走了**：先看 `合并=N`。N>1 却说「没人听」是自相矛盾 —— 那说明
  是我们把新请求交给了死掉的轮次。
- **「防打错」的 UI 不许在搜索跑起来之后再打断它**（11-02 当晚 13 次搜索 10 次是同名第二发：
  确认框按输入防抖，1.3s 时盖在结果页上弹出，一点就 abort 重来）。
- **容差不能有"下限保底"**（10-26）。`tightness` 的 `max(1, len(kw)//3)` 让两字书名也吃
  「多一个字」的容差 → 「嘿兄弟」「兄弟盟」成《兄弟》的确切命中、日志写 `确切=2`。两字必须零容差。
- **「学会了」不等于「这个站行了」**（11-06）。`save_search_tpl()` 清 `search_fail`，而
  `should_try_learn()` 拿它当放弃门槛 → 门槛永远够不到 → 5 个站每天「学会→判死→再学」6 天。
  **模板账 ≠ 站账**（站级 `tpl_dead` 跨模板累计 + 7 天冷却）。放弃门槛读的计数，先问**谁清零它**；
  日志里「已失败 N 次」天天写 1，就先怀疑计数被清零。
- `www.xizids.com` 301→`www.xuanhuanbiquge.com` 是同一个站两个 host，一次搜索打两遍。
- **别为"可搜源 N 个"高兴**（11-06）。29 个里对《三体》只有 **5 个**真给出含关键词的书；
  15 个一条都抽不出（jcxs/xizids/xuanhuanbiquge 是 3KB JS 空壳），9 个抽 20~144 条却没有一条
  标题含关键词（模板不带 kw、吐推荐位）。学站准入该问「控制实验里抽出过几条」
  （复跑：`tools/probe_pool_health.py`，要在服务器上跑，本机 DNS 解析不了这些站）。
- **「有结果」≠「有能读的结果」**（10-27）。死链也能是确切命中（tight=1.0/score=100）：
  唯一候选 0 章，收手门被它喂饱 → 「本地一条可读都没有、出去找」一次都进不去。
  修完连着问：这个"够用了"认的是**可读**还是**像**？
- **门票问错问题**（10-27）。`exhausted` 答的是"我们等够了没"，不是"还能不能救"。
- **「某个站 0 产出」先问是不是我们自己的问题**（10-30）。同一现象三种病因：
  ①站里没这本书②我们打太快被限速（杰奇 CMS 全线 30 秒一次）③模板真坏。只有③该判死。
  ①②已各加判据（`_looks_like_empty_result` / `_looks_like_busy_page`），命中都**不碰** shape。
- **「按 URL 形状分组」先问 id 是不是编码过的**（10-31）。cn.shubaoc.com 用 base32 当章节 id
  （`1u0ri`）→ 42 章被拆成 42 个单条组、全都够不到 `min_items=8` → 判成"没有目录"。已补
  `_is_slug_seg`；slug 里的数字也别当章节号。
- **判据只认一种文体，就等于只服务一种书**（10-31）。`toc_quality` 只认「URL 单调 + 第N章」，
  散文集目录叫「自序」「第一辑 阿勒泰文字…」→ 三天三本冷门书全栽。第三条证据是**页面自己说的**：
  有「章节列表」+ 链接都挂在本页这本书下 + 是页面主要链接群。
- **"质量分选优"会被噪声反超**（10-31）。单调递增的「猜你喜欢」得 0.35，而认不出目录区的
  真目录得 0.0 → 噪声赢 → 用户点开一本书、目录是别人的书。凡多路候选打分选一，都要有一条
  **结构性否决项**（"挂不挂在本页这本书下"）且排在分数前面。
- **一次搜索会改全局状态时，必须把变化打进这次搜索的日志**（10-30）。源池 22→15 曾经
  零字段，只能事后 diff `registry.json` 才发现。已加 `源池=A→B`。取不到打 `?`，不补 0。
- **写完 ≠ 上线**（10-30）。判"上线了"只看两条：服务重启时间晚于提交时间、md5 与本地一致。
- **测试要自带数据，别靠环境**（10-30）。本机 `cache/registry.json` 的 searchable 是 0，
  于是"两头相等"恒真，反证当场报"存活 2 条"。凡断言里的数字来自环境，先伪造它。
- **测试只走一条开关组合 = 另一条完全没覆盖**（10-27/10-31）。`test_discover_fallback` 全用
  `probe=False` 时"联网→探测"从没跑过；10-31 又栽一次：`grep preempt tools/test_*.py` 是**空的**，
  给 `stats` 加 `web_verify` 时在 preempt 分支读了一个只在串行分支赋值的变量 → 线上 500。
  加字段先问：这条链上**每个分支**都给过它值吗？⚠ 同进程测试共享熔断器：新场景必须用
  **独立源名**（`hang8`），否则被前面场景拉黑、源压根不挂 → 测试"绿的是空转"。
- **反证靶点也是一种判据**（10-24/10-26）。改了收手/超时路径先查靶点还在不在；
  靶点**别挂在 docstring 上**（改一句说明就脱节）；同一语句出现两处会「多处命中」，
  `test_ship_chain` 会红。收紧某个判据前，**先拿线上真实数据跑新旧两版对比**
  （10-26 用线上候选池跑 10 个两字书名，确认没有一本变空）。

## 工具与环境的坑
- `env -u http_proxy … python -c "多行"` 在本机 Git Bash 下静默无输出 → 用 `unset … ; python …` 或写文件。
  **`ssh` 同样中招**：`env -u … ssh … 'cmd'` 返回空且 exit=0，看起来像"服务器没日志"。ssh 直接打。
- 本机 `curl` 打线上返回空（连 `-w` 都不打印）→ 用 `.venv/Scripts/python.exe` + urllib。
- `tools/mutate.py` 与 `tools/ship.py` **不能并发**；看到"测试期间源码被外部改动"先查别的会话。
