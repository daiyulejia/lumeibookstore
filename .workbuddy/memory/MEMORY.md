# 项目长期记忆（novel-downloader / 噜妹书院）

## 一、复盘纪律
- 线上日志优先（`~/noveldock/logs/app.log`）。开工第一件事是**探可达性**
  （22/80/443/8000 + ICMP + 境外节点）：**「零搜索」有两种，日志里长得一模一样** ——
  ①没人搜 → 能写"没有新案例"；②实例不可达 → 只能写"**没有数据可判**"。
  历史上的"连续三天没有新案例"里就藏着一次产品下线（11-13 起至今未恢复）。
- 「0 条」的两种含义必须分开：**书没有** vs **源挂了**。`search.done` 的
  `答/挂/未回/熔断/自限/卡满/确切` 要自洽（`答+挂+未回+熔断+自限 == 应搜总数`），
  未回/熔断/自限**都要点名**。`候选=0` 不是唯一形态：`候选=4 确切=0` 同样是搜不到。
- 只读线上数据；重启交给 `tools/sync_cloud.py`；禁删/禁建/禁续费实例。
- 收手可以，**不许沉默地收手**：撞预算/超上限都要把还欠多少（`pending`）写进返回值或日志。

## 二、判据本身会说谎（最高频母题，踩了 20 多次）
- **`return []` / `return None` 会把相反结局合成一笔**（11-19 百度 → 11-20 必应 →
  **11-24 冷却档位**）。凡降级/兜底/「拒绝」的返回值先问：它合并了哪几种结局？
  第三次形态不是返回值而是**冷却时长**：「抖动」与「被封」都写 600 秒，处置相反。
- **「够多」≠「够好」**（10-24/10-25/11-18）。用条数/源数当质量代理会被噪声喂饱：
  词典页/新闻页/推荐位都能凑数，而收手门/第二问门只看数字。要有**确切命中**门。
  凡"候选=1、确切=0"这种算术不成立的行，先怀疑口径。
- **「让路」装满 4 门里的 3 门 = 没装**（11-25）。收手① 数的是 `len(raw)`（撞词也算），
  「11 噪声+1 确切」1.5s 就把还要跑 3s 的 registry 切断；而日志同一行写着
  「放弃 registry…；按自身预算等过 registry」——**自相矛盾的一行就是漏门的指纹**。
- **一个词只许指一件事；默认值不许写在真值之后**（11-26）。`可读=` 数的是 available
  （目录能开），前端绿标用 readable（正文抽样）→ 日志写 `可读=1`、用户一个字读不到。
  第二形态：`web_gave = 0` 排在 `join()` **之后**，把「兜底交回 1 条」冲成 0。
  凡统计字面量写进 `log_event`、凡跨分支默认值，先问：**它和用户看到的是同一个数吗？**
- **判据依赖「页面文案」= 只服务一种页面**（10-31/11-21）。证据要取**结构**
  （整组链接挂本书下≥95% + 主要链接群≥50% + 单调数字列 + 书本路径≥两段）。
  判据里出现"页面自己说"，就问：**页面不说的时候呢**？
- **判据的窗口也是判据**（11-20）：`body[:4000]` 让下游反向断言空转。
  截断/取头部/取前 N 条都会让断言恒真。**沉默地截断**同样有毒（要点名 `+N`）。
- **去重窗口的锚点必须是「第一枪」，不能是「最近一枪」**（11-28）。
  `search_shape_at` 写在 if 外面 → 被合并的观察也刷新锚点 → 间隔 <180s 就永远
  落回窗口内 → 一场风暴被计成 **0 票**（设计目标是 1 票），站永不作废。
  凡"压成 N 次只算一次"，先问：**这一次是从哪儿开始数的**？
  第二形态：测试替身把时间戳清零（`_obs()` 直接置 0）＝把被测的时间逻辑替掉了。
- **只进不出的判据 = 资产单向缩水**（11-17 `is_healthy`、11-21 `_verify`）。
  凡"越过某线就排除"，先问**它怎么回来**（`probation_sites()` / `worth_recheck()`）。
- **两条独立判据共用一个前提 = 一条判据**（11-27）。模板作废与控制实验都写着
  `search_hit == 0`，一次「偶然命中」（不认词的站回整站推荐位，用户搜的那本恰好在
  里面）同时击穿两道门 → 3 个 host 被判中 31/47/58 次仍占 30% 源池。
  凡两处写着同一条件，先问：**它会不会被一次偶然永久翻转？**
- **账本字段必须有读者**（11-27）。`search_kwblind` 记了 58 次、全仓零读取 →
  "判中"等于没判。已加 AST 闸门（`cur["x"]=int(...)+1` 的计数器必须有读点，
  只写不读即红；白名单必须写理由）。
- **闸门装在一个入口上等于没装**（11-06/11-11/11-16/11-17）。立判据前先数"这件事有几个
  入口"：谁清模板、谁清计数、**谁删站**。共同点要按**共同点 grep** 收敛成一份 + AST 闸门。
- **放弃门槛读的计数，先问谁清零它**（11-06 `save_search_tpl` 清 `search_fail` → 门槛永远够不到）。
  **模板账 ≠ 站账**：站级 `tpl_dead` 跨模板累计 + 7 天冷却。
- **「连续 N 次」要问：这 N 次会不会是同一瞬间数出来的**（11-01/11-16）。
  `search_shape` 已加 180s 观测去重；**熔断器 `note_fail` 与学站 `note_search_fail`
  仍按次数，仍能被一瞬间喂饱 —— 未修**（改它要重写 26 处老判据）。
- **判据固化了旧行为时，红的是判据不是产品**（11-01）。
- **测试要自带数据**（10-30）：断言里的数字若来自环境（本机 `searchable=0`）会恒真。
  **同进程测试共享熔断器**：新场景必须用独立源名（`hang8`），否则"绿的是空转"。
  **换了几个桩就要还原几个**（11-19 只还原 `_bing`，桩泄漏污染后面所有组）。
  **加字段先问：这条链上每个分支都给过它值吗**（11-15 preempt 分支读了只在串行分支赋值的
  变量 → 线上 500）。**加参数先数有几个替身**（11-21 三个桩签名不匹配，TypeError 被吞）。
- **判据不许赌"异步还没开始"**；假时钟必须自己推进时间。
  **桩要等状态**（"真有人并进来"）而不是等时长，否则两个并发用例被"天然串行"喂绿（11-23）。

## 三、时间与预算
- **源必须有自己的墙钟上限**（wikisource 186.9s→6s、wyshu→6s、taiminc 7.3s）。
- **「声明的时间预算」比调用方收手点长 = 没声明**（11-09 `RegistrySource` 7.0s vs 软截止 6.0s
  → 30 个站产出 12/17 次被整批扔）。凡"我内部要跑 N 秒"，先问调用方肯等几秒 → `Source.budget_s`。
- **httpx 的 timeout 是分操作的，不是墙钟**；**退避睡眠不认表**（11-15 声明 6s 实测 7.33s）。
- **「默认超时」是隐形墙钟**（`fetch_text` 25s vs 榜单整轮 25s；引擎请求 25s vs 联网 32s → 已给 8s）。
- **调度算术要按「批数」算**（11-16）：7 类 / 3 并发 = 3 批 → 38.4s ≫ 25s 必然少一类且不报错。
- **自建索引型来源在"调用方 1.5s 收手"下 100% 白跑**：修法不是加预算，是**搜索只读缓存、
  冷的把构建踢后台**（wyshu 冷 0ms → 后台 794 本 → 下一轮 13 条）。
- **核实与下载需求相反，不能共用一根旋钮**（探测 3 页/3s vs 下载 40 页/25s）→ `read_toc(full=…)`。

## 四、并发：缓存 ≠ 去重
- **同一瞬间几个人在要同一件事**（11-01/11-22/11-23 三次）。冷缓存下 N 个同 key 请求各自重做
  → 16 个同名搜索把引擎打成返回别的页面（7/8 空）。修法：`searchflight.py`（在飞合并）与
  `utils.single_flight()`（跑完即摘，**不是缓存**）。
- **单飞退化成缓存是"最像修好了"的坏法**：只有「下一次必须重跑」能抓它，而那条判据
  **必须换一个线程**调（同线程重入是"自己人直接跑"，恒绿）。
- **「先查状态、后动手」中间隔着一次 await 就是一道缝**（11-04）→ 新请求挂到**弃轮**上 →
  1.5s 拿到 `候选=0`。修法：把「拿一轮」和「挂上去」收进同一把锁。
  `aborted=True` 也≠用户走了：**先看 `合并=N`**。
- **连不上 ≠ 产品挂了**：产品崩了给 `refused`（有回包）；四端口一致超时 + ICMP 不回 = 主机级。

## 五、站点与源池
- **空结果 ≠ 挂**（走 `note_ok`）；反过来，源"建索引/抓页全失败"却返回 `[]` 必须 `note_error`。
- **「本地保护」≠「远端故障」**（11-16）：限流冷却/熔断跳过/预算收手都是**我们自己决定不做**，
  必须分开归因，否则日报写"这个站坏了"、处置却是"降速等它"，正好相反。
  `errors.LocalCooldown` + `is_local_cooldown()` + `自限=` 一格。
- **某个站 0 产出先问是不是我们自己的问题**：①站里没书 ②我们打太快被限速（杰奇 CMS 30s）
  ③模板真坏。只有③该判死；①②命中时**不碰** shape。
- **「有书链接」≠「这是搜索页」**：`raw>0 且 hits=0` 混记 `FAIL_EMPTY` 会把"没书"和
  "不认关键词"合成一笔（处置相反）。判据：控制词也抽回真词 80%+ 一屏 = 不认词。
- **别为"可搜源 N 个"高兴**：29 个里对《三体》只有 5 个真给出含关键词的书（`probe_pool_health.py`，
  **必须在服务器上跑**）。11-27 又量出 10 个里有 3 个是同一个不认词的站的三个 host。
- **一次搜索会改全局状态时，必须把变化打进这次搜索的日志**（`源池=A→B`、删站删书要点名）。
  取不到打 `?`，不补 0。

## 六、目录与正文
- **「有结果」≠「有能读的结果」**：死链也能是确切命中（tight=1.0），收手门被它喂饱 →
  「本地一条可读都没有、出去找」一次都进不去。
- **「账本全绿」≠「用户拿到的是全的」**（11-22）：2166 章只交 104 章，账本仍是 `可读=1`
  → `verify.ok` 加 `不全=`。
- **分页器认不出 = 长书永远只有第一页，而且静默**：杰奇 `/html/1/9001_2/`、数字槽位
  `/book/57620/2/`、下划线 `/0/98/index_2.html`。凡"循环里提前退出"，
  问一句：**下游怎么知道它没做完**？
- **JS/反爬开不了 ≠ 没有源**（11-24）：番茄/品书斋能被 Bing 找到但 `page_of()` 判 unknown；
  反爬时好时坏（《素食者》4 次"疑似无源"，起点好使那一刻就是 42 章）。

## 七、工具与环境的坑
- **开工先 `git status`**（11-13 工作区躺着没还原的突变注入，在脏树上 ship = 拿坏代码上线）。
- **写完 ≠ 上线**：判"上线了"只看两条 —— 服务重启时间晚于提交时间、md5 与本地一致。
- **有测试 ≠ 有保护**：判据必须进 `tools/ship.py` 的 `STATIC_SUITES`/`LIVE_SUITES`，
  且 `grep <文件名> tools/ship.py tools/mutate.py`。账要在日志/状态接口里，不能只在返回值里。
- **反证靶点是判据的一部分**（10-24/10-26/11-18/11-24 栽四次）：改收手/超时/记账/搬代码那几行前，
  先 `grep` 它是不是靶点，靶点文本**从源码复制**。**搬走一段代码 = 靶点脱节 = 静默失效**。
- **`mutate_pending.json` / `mutate.lock` 残留**：残留会被写回、**静默回滚当天的新代码**
  （已加 60 分钟时效闸门）；锁按 pid 判活，死了删 `dist/tmp/mutate.lock`。
  `mutate.py` 与 `ship.py` **不能并发**。
- **测试判据也要防"顺手把旧 bug 写成断言"**：先问 ①这量会不会只因环境变（**别用耗时阈值**）
  ②把功能拆掉这条还绿吗 ③只验正向没验反向吗。
- **Windows 管道 = GBK**（启动横幅的 `⇄` 让进程在 `uvicorn.run()` 之前就退，542 次/上午）：
  修法是**加固 stdio**（只放宽 `errors`），判据必须自己构造 `PYTHONIOENCODING=gbk`。
- `env -u http_proxy … python/ssh` 在本机 Git Bash 下**静默无输出且 exit=0** → 用 `unset … ; …`，
  ssh 直接打。本机 `curl` 打线上返回空 → 用 `.venv/Scripts/python.exe` + urllib。
- 本机 `tools/probe_search.py --local` 是"没有线上流量时"唯一可用的尺子；它自己坏了会伪装成
  产品坏了（`schema_error` 单独判，绝不混进"0 条"）。
