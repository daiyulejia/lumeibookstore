# 项目长期记忆（novel-downloader / 噜妹书院）

## 每日搜不到复盘的硬规矩
- 线上日志优先：`~/noveldock/logs/app.log`（当天）+ `app.log.<日期>`（前一天，零点轮转）。
- 判「0 条」的两种含义必须分开：**书没有** vs **源挂了**。
  `search.done` 带 `答=/挂=/未回=/熔断=/卡满=/确切=`（10-23 四格、10-24 加确切、
  10-25 加「熔断」第五格）：**答+挂+未回+熔断 必须等于应搜总数**，未回/熔断后都要点名。
  旧字段 `超=` 已删。
- ⚠ `候选=0` 不是唯一的"搜不到"。`候选=4 确切=0` 同样是搜不到（4 条撞词），
  日报必须两个一起看。只要复现能搜到，就**不进** `known-missing.md`。
- 引擎上限：扇出 20s、总预算 22s（联网兜底那轮 32s）；源自带上限统一 6s。

## 已证实的病灶（别再重犯）
- **源必须有自己的墙钟上限**。否则引擎放弃后它仍活几分钟，吃线程和连接池
  （共享 httpx 只有 10 条）。已修 wikisource 186.9s→6s、wyshu→6s。新加源先问这一句。
- **熔断器只认"跑完的失败"**：卡死的 future 永不完成 → `take_error()` 拿不到 → 永远学不会。
  墙钟到点必须清算 pending。
- **空结果 ≠ 挂**（走 `note_ok`，否则搜几本冷门书全站拉黑）；**反过来也成立**：
  源"建索引/抓页全失败"却返回 []，必须 `note_error`，别伪装成"没这本书"。
- **「够多」≠「够好」**（10-24）。收手看「候选条数/答的源数」会被噪声骗：registry 一源吐
  40 条「嘿兄弟」，1.5s 就判"够了"，慢源的独有正主被扔掉且全程不报错。必须有确切命中门。
- **"有没有结果"与"是不是这本书"是两件事**（10-24）。`候选=4` 同形对应"有正主"和
  "4 条撞词" —— 不是判据太松，是没埋点。凡是用户能感知的差异，日志里必须有字段。
- **埋点要埋在人看得见的那批对象上，不能埋在中途累加值里**（10-25）。`确切` 原来取扇出
  循环的累加值，而联网兜底交回的候选不过那个循环 → "救回来了"被记成 `确切=0`。
  凡"候选=1、确切=0"这种**算术上不成立**的行，先怀疑口径，别怀疑书。
- **被跳过的对象也要进分母**（10-25）。熔断跳过的不进账，"全部源都在熔断"就成 `答=0/0`：
  加得起来、零信息，和"搜遍了都没有"一模一样。已加「熔断=N(名字)」格 + 全灭时明写一行。
- **日志说"跳过"就必须真的跳过**（10-25）。`logger.info("跳过…")` 后面紧跟
  `self._discover(...)`，还配一段永远到不了的重复分支 —— 不报错、只撒谎，
  而且把 32s 预算撑到 42s。收手可以，不许沉默，也不许说反话。
- **只修写入口 = 半修**。凡"有模板就不再学、有缓存就不再算"的对象，读路径也要幂等自愈
  （`registry._scrub_stale_why()`）。
- **判据自己会说谎**。`search_fail_why` 说的是"那一个模板"的死因，不是"这个站行不行"。
- **容差不能有"下限保底"**（10-26）。`tightness` 的 `max(1, len(kw)//3)` 让两字书名
  也吃「多一个字」的容差 → 「嘿兄弟」「兄弟盟」成《兄弟》的确切命中，`rank()` 只留它们、
  收手门被喂饱、日志写 `确切=2`。短书名的容差必须是 0：多一个字就是另一本书。
- **只持久化"热态"，重启就丢掉冷态那半**（10-26）。熔断器只写「仍在冷却中」的条目，
  冷却一到期的连 `streak` 一起消失 → 15m→30m→60m 从没生效过（三天里每次 ship 后都
  倒退）。凡是"满足某条件才落盘"的状态，都要问一句：不满足条件的那部分丢了会怎样。
- **「有结果」≠「有能读的结果」**（10-27）。死链也能是确切命中（tightness=1.0、score=100）：
  《我的阿勒泰》唯一候选探测回"不是目录页"、0 章，收手门却被它喂饱 → 提前收手 →
  `exhausted=False` → 「本地一条可读都没有、出去找」这条分支**一次都进不去**。
  修完要连着问：这个"够用了"的判据，认的是**可读**还是**像**？
- **门票问错问题**（10-27）。`exhausted` 回答的是"我们等够了没"（针对零结果，慢源还可能翻盘）；
  走到联网那行时扇出已结束、没回来的源结果本轮不会再用 —— 提前收手与撞满墙钟
  对本地可读产出**没有区别**。拿它当"还能不能救"的门票，等于问错了问题。
- **测试只走一条开关组合 = 另一条完全没覆盖**（10-27）。`test_discover_fallback` 里
  所有用例都 `probe=False`，于是"本地全灭→联网→探测"这条线上真实路径从没跑过；
  加 probe=True 当场 `AttributeError`。写用例前先数一遍开关组合。
- **慢 ≠ 该砍**（10-22）。"本地有结果就别等联网兜底"是错的：三次慢搜索里联网兜底
  都是唯一救回结果的那一路。本地"已推 6 条"去噪后常只剩 1 条。
- **"只报数不报名字"= 没报**（10-23）。已修：源账、学站预算、自有源预算。
- **反证靶点也是一种判据**（10-24/10-26）。改了收手/超时路径先查靶点还在不在；
  靶点**别挂在 docstring 上**（改一句说明就脱节）；同一语句出现两处会「多处命中」，
  `test_ship_chain` 会红。收紧某个判据前，**先拿线上真实数据跑新旧两版对比**
  （10-26 用线上候选池跑 10 个两字书名，确认没有一本变空）。

## 工具与环境的坑
- `env -u http_proxy … python -c "多行"` 在本机 Git Bash 下静默无输出 → 用 `unset … ; python …` 或写文件。
  **`ssh` 同样中招**：`env -u … ssh … 'cmd'` 返回空且 exit=0，看起来像"服务器没日志"。ssh 直接打。
- 本机 `curl` 打线上返回空（连 `-w` 都不打印）→ 用 `.venv/Scripts/python.exe` + urllib。
- `tools/mutate.py` 与 `tools/ship.py` **不能并发**；看到"测试期间源码被外部改动"先查别的会话。
