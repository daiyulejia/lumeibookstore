# 项目长期记忆（novel-downloader / 噜妹书院）

## 每日搜不到复盘的硬规矩
- 线上日志优先：`~/noveldock/logs/app.log`（当天）+ `app.log.<日期>`（前一天，零点轮转）。
- 判「0 条」的两种含义必须分开：**书没有** vs **源挂了**。
  `search.done` 现在带 `答=/挂=/未回=/卡满=`（2026-10-23 起）：**四格互斥，
  答+挂+未回 必须等于总数**，`未回` 后面点名（例：`未回=4(kunnu8,wikisource,wyshu,xbqg5200)`）。
  旧字段 `超=` 已删 —— 它只是"收手时还没回来的个数"，来源不明，会让人误判成"4 个源超时"。
- 只要复现能搜到，就**不进** `docs/search-review/known-missing.md`（那本清单只放"确认全网无源"）。
- 引擎的硬上限：扇出 20s、总预算 22s（联网兜底那轮 32s）。撞满 20s 的搜索单独统计，它们是"慢到没结果"。

## 已证实的病灶（别再重犯）
- **源必须有自己的墙钟上限**。任何内部带"多次重试 + 退避"的源（wikisource 是典型：
  5 次重试 × 25s 握手 + 递增退避，还串两次查询）在引擎放弃后仍会活几分钟，
  吃线程和连接池（共享 httpx client 只有 10 条连接）。实测 186.9s → 6s 预算后 7.2s。
- **熔断器只认"跑完的失败"**。卡死不返回的源 future 永不完成 → `take_error()` 拿不到 →
  熔断器永远学不到。所以 `engine.search` 在墙钟到点时必须清算 pending（已有实现 + 测试）。
- **空结果 ≠ 挂**。空结果必须走 `note_ok`，否则搜几本冷门书就把所有源拉黑。
- **只修写入口 = 半修**（2026-10-22）。写入侧修好只对"将来会再写一次"的对象有效。
  凡"永不重试/永不重算"的对象（有模板就不再学、有缓存就不再算），
  必须在**读路径**补幂等自愈，否则报的是"修好了"、线上一点没变。
  典型：`registry._scrub_stale_why()` 挂在 `_scrub_and_log()`，重启后自愈 8 条。
- **判据自己会说谎**。`search_fail_why` 说的是"那一个模板"的死因，不是"这个站行不行"；
  看到 `searchable=True` 和「假搜索」同时出现，先怀疑字段过期，别急着当功能 bug 改。
- **慢 ≠ 该砍**（2026-10-22）。想砍"本地有结果就别等联网兜底"是错的：
  三次慢搜索里联网兜底都是唯一救回结果的那一路（联网发现 5/6/1）。
  本地"已推 6 条"不等于"有 6 条可用"，去噪后常只剩 1 条。
- **"只报数不报名字"= 没报**（2026-10-23）。凡是"N 个源没回来 / 还剩 N 个没学完"
  这类日志，不带名字就永远分不清"预算太小"和"某站永远慢"（处置相反）。
  已修：源账、学站预算、自有源预算三处。反证 `mutate.py 源账`。

## 工具与环境的坑
- `env -u http_proxy … python -c "多行代码"` 在本机 Git Bash 下会静默无输出 → 用 `unset … ; python …` 或写成文件。
  **`ssh` 同样中招**：`env -u … ssh … 'cmd'` 返回空且 exit=0，看起来像"服务器没日志"。ssh 直接打，别加前缀。
- 本机 `curl` 打线上 HTTP 返回空（连 `-w` 都不打印）→ 用 `.venv/Scripts/python.exe` + urllib 访问 API。
- `tools/mutate.py` 与 `tools/ship.py` **不能并发**（两个会话同时跑会把源码替换两次）；
  mutate 现在会报"测试期间源码被外部改动，这一条不算数"，看到这句先查是否有别的会话在写文件。
