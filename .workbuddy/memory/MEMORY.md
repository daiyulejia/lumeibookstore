# 项目长期记忆（novel-downloader / 噜妹书院）

## 每日搜不到复盘的硬规矩
- 线上日志优先：`~/noveldock/logs/app.log`（当天）+ `app.log.<日期>`（前一天，零点轮转）。
- 判「0 条」的两种含义必须分开：**书没有** vs **源挂了**。
  `search.done` 带 `答=/挂=/未回=/卡满=/确切=`（10-23 起四格互斥，10-24 起加确切）：
  **答+挂+未回 必须等于总数**，`未回` 后面点名。旧字段 `超=` 已删。
- ⚠ `候选=0` 不是唯一的"搜不到"。`候选=4 确切=0` 同样是搜不到（4 条撞词），
  日报必须两个一起看。只要复现能搜到，就**不进** `known-missing.md`。
- 引擎上限：扇出 20s、总预算 22s（联网兜底那轮 32s）；源自带上限统一 6s。

## 已证实的病灶（别再重犯）
- **源必须有自己的墙钟上限**。带"多次重试 + 退避 + 串行打 N 页"的源在引擎放弃后
  仍会活几分钟，吃线程和连接池（共享 httpx 只有 10 条连接）。已修：wikisource（186.9s→6s）、
  wyshu（建 8 页索引 + 8 次拼音兜底 →6s）。新加源先问：它自己有上限吗？
- **熔断器只认"跑完的失败"**。卡死不返回的 future 永不完成 → `take_error()` 拿不到 →
  熔断器永远学不到。墙钟到点必须清算 pending。
- **空结果 ≠ 挂**。空结果走 `note_ok`，否则搜几本冷门书就把所有源拉黑。
  **反过来也成立**：源"建索引/抓页全失败"却返回 []，必须 `note_error`，别伪装成"没这本书"。
- **「够多」≠「够好」**（2026-10-24）。收手判据只看「候选条数 / 答的源数」，就会被噪声骗：
  registry 一个源吐 40 条「嘿兄弟/兄弟盟」，1.5s 就判"够了"，把慢源的独有正主扔掉，
  全程不报错。判据里必须有「至少一条确切命中」（`tight_hits`），软截止留作无条件上界。
- **"有没有结果"与"是不是这本书"是两件事**（2026-10-24）。`候选=4` 在日志上完全相同地
  对应"有正主"和"4 条撞词"—— 不是判据太松，是**没埋点**。凡用户能感知的质量差异，
  日志里必须有对应字段，否则日报永远看不见。
- **只修写入口 = 半修**。写入侧修好只对"将来会再写一次"的对象有效；凡"有模板就不再学、
  有缓存就不再算"的对象，必须在**读路径**补幂等自愈（`registry._scrub_stale_why()`）。
- **判据自己会说谎**。`search_fail_why` 说的是"那一个模板"的死因，不是"这个站行不行"；
  看到 `searchable=True` 和「假搜索」并存，先怀疑字段过期。
- **慢 ≠ 该砍**（2026-10-22）。"本地有结果就别等联网兜底"是错的：三次慢搜索里
  联网兜底都是唯一救回结果的那一路。本地"已推 6 条"去噪后常只剩 1 条。
- **"只报数不报名字"= 没报**（2026-10-23）。不带名字就分不清"预算太小"和"某站永远慢"。
  已修：源账、学站预算、自有源预算。反证 `mutate.py 源账`。
- **改了收手/超时路径，先查反证靶点还在不在**（2026-10-24）。给收手加"及时唤醒"后，
  `hit_deadline=True 且有结果` 这个场景消失了，「卡满」那条突变随即变成没牙 ——
  ship 当场拦下。场景搬家了，靶点要跟着搬。

## 工具与环境的坑
- `env -u http_proxy … python -c "多行"` 在本机 Git Bash 下静默无输出 → 用 `unset … ; python …` 或写文件。
  **`ssh` 同样中招**：`env -u … ssh … 'cmd'` 返回空且 exit=0，看起来像"服务器没日志"。ssh 直接打。
- 本机 `curl` 打线上返回空（连 `-w` 都不打印）→ 用 `.venv/Scripts/python.exe` + urllib。
- `tools/mutate.py` 与 `tools/ship.py` **不能并发**；看到"测试期间源码被外部改动"先查别的会话。
