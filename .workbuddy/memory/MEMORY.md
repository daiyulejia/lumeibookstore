# 项目长期记忆（novel-downloader / 噜妹书院）

## 每日搜不到复盘的硬规矩
- 线上日志优先：`~/noveldock/logs/app.log`（当天）+ `app.log.<日期>`（前一天，零点轮转）。
- 判「0 条」的两种含义必须分开：**书没有** vs **源挂了**。
  `search.done` 带 `答=/挂=/未回=/熔断=/自限=/卡满=/确切=`（10-23 四格、10-24 加确切、
  10-25 加「熔断」、11-16 加「自限」第六格）：**答+挂+未回+熔断+自限 必须等于应搜总数**，
  未回/熔断/自限都要点名。旧字段 `超=` 已删。
- ⚠ `候选=0` 不是唯一的"搜不到"。`候选=4 确切=0` 同样是搜不到（4 条撞词），
  日报必须两个一起看。只要复现能搜到，就**不进** `known-missing.md`。
- 引擎上限：扇出 20s、总预算 22s（联网兜底那轮 32s）；源自带上限统一 6s。
- **「零搜索」有两种，日志里长得一模一样**（11-15）：①服务在线、没人搜；②实例不可达、
  日志压根拉不到。①能写"没有新案例"，②只能写"**没有数据可判**"。
  开工第一件事是探可达性（22/80/443/8000 + ICMP + 境外节点），
  历史上的"连续三天没有新案例"里就藏着一次产品下线。

## 已证实的病灶（别再重犯）
- **重复的同一个请求不合并 = 自己把自己打成搜不到**（11-01）。8 秒 16 个同名同参请求各起
  一轮引擎 → 搜索引擎返回**别的页面**，8 并发 7/8 `候选=0`，单独搜 `候选=2 可读=2`。
  修法 `app/searchflight.py`（在飞合并，**不是缓存**）：收手看「还有没有订阅者」。
- **缓存 ≠ 去重：缓存只在"跑完之后"才有值**（11-23，同一条母题第三次）。冷缓存下 N 个同 key
  请求全部 miss、各自把最贵的活重做一遍 —— 11-01 是搜索（16 个同名请求把搜索引擎打成
  不认识词）、11-22 是长书分页（两份 21 页 → 线上 107s、日志全绿）、11-23 量到
  `page_of()` 两线程解析 2 次、`cached()` 的 producer 压根没合并（7 个调用点全是目录级）。
  已加 `utils.single_flight()`（跑完即摘，**不是缓存**）。问法：同一瞬间几个人在要同一件事？
- **单飞退化成缓存是"最像修好了"的坏法**（11-23）。所有合并断言都绿，只有「下一次必须
  重跑」能抓它；而那条判据**必须换一个线程**来调 —— 同线程重入会被当成"自己人直接跑"
  （防死锁的正确行为），拿它验摘牌恒绿。第一版就写错了，是反证报"存活"才发现的。
- **判据缺同步点 = 被"天然串行"喂绿**（11-23）。两个并发用例都写了"两路各跑一次"，但没人
  在中间等：第一路早跑完了，突变照绿。桩必须等**状态**（"真有人并进来"）而不是等时长。
- **反证工具自己会把工作区回滚**（11-23）。`mutate_pending.json` 存的是"写坏之前的原文"，
  昨天的残留今天启动时被写回 → 今天新加的一整段代码**静默消失**，工具只打一行「已还原」，
  接着报"基线就是红的"。已加时效闸门：超过 60 分钟的残留只点名、不回写。
  ⚠ 自己改自己的突变，锚点必须**拼串**构造 —— 整句写进清单会命中 2 处（定义 + 清单）。
- **凡是"连续 N 次"的判据，都要问：这 N 次会不会是同一瞬间数出来的**（11-01、11-16）。
  ①`search_shape` 已加观测去重（180s 窗口，不是耗时阈值）；②**熔断器 `note_fail`
  和学站 `note_search_fail` 仍按次数**，仍能被一瞬间喂饱 —— **未修**；③11-16 又冒出
  第三种形态："同一件事被数 N 遍"——冷却期内每轮搜索都记一次失败（已修，见下条）。
- **判据固化了旧行为时，红的是判据不是产品**（11-01）：「连调三次触发作废」的老用例变红，
  是因为它们把旧 bug 写成了断言，得改成「三次**独立**观察」，不是把产品改回去。
- **源必须有自己的墙钟上限**。否则引擎放弃后它仍活几分钟，吃线程和连接池
  （共享 httpx 只有 10 条）。已修 wikisource 186.9s→6s、wyshu→6s。新加源先问这一句。
- **熔断器只认"跑完的失败"**：卡死的 future 永不完成 → `take_error()` 拿不到 → 永远学不会。
  墙钟到点必须清算 pending。
- **空结果 ≠ 挂**（走 `note_ok`，否则搜几本冷门书全站拉黑）；**反过来也成立**：
  源"建索引/抓页全失败"却返回 []，必须 `note_error`，别伪装成"没这本书"。
- **「本地保护」≠「远端故障」**（11-16）。`fetch_text` 在同域冷却期内直接抛错、一个请求
  都不发 —— 那是我方保护，不是站挂了。引擎把它当失败喂熔断器 → 冷却 120s 却熔断 300s
  → streak+1 → 10/20/40 分钟封顶 8h：**越保护越死**。凡"我们自己决定不做的动作"
  （限流冷却 / 熔断跳过 / 预算收手）都必须与"对方坏了"分开归因、分开记账，
  否则日报写"这个站坏了"，处置却是"降速等它"，正好相反。已加 `errors.LocalCooldown`
  + `search.done` 第六格 `自限=`，两个入口（抛异常 / `take_error()` 交回字符串）都要判。
- **调度算术要按「批数」算，只算单类等于没算**（11-16）。榜单注释写"最坏 12.8s < 25s"，
  而 7 类 / 3 并发 = 3 批 → 38.4s ≫ 25s，**必然少一类**且不报错。凡"每批最多 X 秒"
  的设计，先问一共几批；判据写成 `批数 × 单类最坏 ≤ 预算`（纯常量关系，不碰耗时）。
- **「够多」≠「够好」**（10-24/10-25）。收手看「候选条数/答的源数」会被噪声骗，必须有确切
  命中门；`确切` 曾取扇出循环的累加值，而联网兜底交回的候选不过那个循环 → 记成 `确切=0`。
  凡"候选=1、确切=0"这种**算术上不成立**的行，先怀疑口径，别怀疑书。
- **「声明的时间预算」比调用方的收手点长，等于没声明**（11-09）。`RegistrySource` 内部 7.0s，
  而引擎软截止 6.0s、常态收手点才 3.5~4.5s → 30 个站的产出 12/17 次被整批扔掉，
  它却"账本自洽"。凡"我内部要跑 N 秒"的组件，先问调用方肯等几秒；凡"账本加起来对"的复盘，
  再问一句「这个源没答，是它慢还是我们不要它了」。
- **httpx 的 `timeout` 是分操作的，不是墙钟**（11-09）。`www.taiminc.com` 给了 3.5s 却跑
  7.3s（慢速吐字节），"已设超时" ≠ "有上限"。
- **「预算是承诺，不是墙钟」**（11-15）：退避**睡眠**不认表、分操作超时相加，都能让
  声明 6s 实测 7~10s —— 查"预算有没有牙"要顺着每一处 `sleep` 和每一次发请求看。
- **自建索引型来源在"调用方 1.5s 就收手"下会 100% 白跑**（11-15）。修法不是加预算、
  也不是声明 `budget_s` 让引擎等（命中率 2/12），而是**搜索只读缓存、冷的把构建踢到后台**。
- **被跳过的对象也要进分母**（10-25）。熔断跳过的不进账，"全部源都在熔断"就成 `答=0/0`。
  已加「熔断=N(名字)」格 + 全灭时明写一行。
- **「先查状态、后动手」中间隔着一次 await，就是一道缝**（11-04）。`acquire()` 在处理函数里跑，
  `subscribe()` 要等生成器第一次 `__anext__()`；老请求在这道缝里断开 → 新一轮挂到**弃轮**上 →
  引擎立刻收手 → 用户 1.5s 拿到 `候选=0`。修法不是加判断，是把「拿一轮」和「挂上去」
  收进同一把锁（`FlightBook.subscribe`）。`aborted=True` 也≠用户走了：**先看 `合并=N`**。
- **防呆 UI 不许在操作跑起来之后再打断它**（11-02：确认框在搜索 1.3s 时盖上来，
  一点就 abort 重来，13 次搜索 10 次是同名第二发）。
- **容差不能有"下限保底"**（10-26）。`tightness` 的 `max(1, len(kw)//3)` 让两字书名也吃
  「多一个字」的容差 → 「嘿兄弟」成《兄弟》的确切命中、日志写 `确切=2`。两字必须零容差。
- **「有几个入口」要按「共同点」grep，不是按上次改过的符号**（11-17）。11-16 修「自限流不是
  源故障」时 grep 的是 `note_fail`（熔断器），只改了 engine/ranks；而这批入口的共同点是
  `classify_fetch_error`（**6 处**各手写一遍）。已收敛成 `registry.site_fault_why()`，
  并加 **AST 闸门**（只许一个调用点，且扫描器要自证"确实扫到那 1 次"，否则判据恒真）。
- **健康判据只有死亡线、没有复活通道 = 资产单向缩水**（11-17）。越线（`down > 2*ok`）后同时被
  `searchable_sites()` 和 `discovery._verify` 排除 → 永远拿不到下一次 ok → 计数**冻结在
  `down == 2*ok+1`**（库里 4/4 个模板站全停在这个值上，就是指纹）。已加 `probation_sites()`
  试用通道（每次 2 个 / 每站 6h / 一次成功即复活 / **不计入** `sites_searchable`）。

  「只看指纹不看体量」的突变当场存活。截断/取头部/取前 N 条，都会让下游断言恒真。
- **「候选全灭」里只要有一个站是被反爬，就不许升级成「确认全网无源」**（11-20）。
  《素食者》被关了 4 次"疑似无源"，今天起点好使那一刻就是 42 章 —— 反爬是时好时坏的，
  "我们开不了页"和"站上没有"必须分开写进判定依据。
- **只有一个来源时，「问法」就是召回率**（11-19）。discovery 两个引擎死一个后，候选供给 =
  1 个引擎 × 1 种查询串 → 冷门书只剩 1~3 条候选，核实再准也没用。同一 Bing 把「书名」
  换成「书名 小说」第一屏就出现真书页（《遥远的救世主》0→33 章）。加话要设**计数**门槛
  （候选 <N 才加问），别设耗时；第二轮不许重置 per_host/去重，否则一个站占两倍名额。
- **「第一次见到它」不是「它变了」**（11-19）。`is_healthy({})` 对空记录返回 False，
  于是新站第一笔账（哪怕失败）被判成"越过死亡线回来了" → `site.revive 成功=0 挂=1 原因=成功一次`。
  而试用通道正是拿 `site.revive` 当验收判据。凡打"状态变化"日志，先判这个对象此前存在吗。
- **测试里换了几个桩，就要还原几个**（11-19）。`finally` 只还原 `_bing`、`_baidu` 的桩
  一路泄漏到后面所有组，新加的判据第一遍测的是**上一组的残骸**，而且不报错。

- **判据不许赌"异步还没开始"**（11-15）。断言"后台没抓取"时后台可能已经抓了（第一遍绿第二遍红）；
  同步路径用只记账的桩问，异步那半单独验。**假时钟必须自己推进时间**，否则"预算用完"永远不来，
  判据报红**而产品是对的**。

- **「账本全绿」≠「用户拿到的是全的」**（11-22）。长书目录只下到前 100 章（2166 章的书交
  104 章），而 `search.done` 一直 `候选=1 成书=1 可读=1` —— 账本只数"有没有"，不数"全不全"。
  凡"我们交出去了"的结论，先问：那份东西的**完整度**谁验过？已给 `verify.ok` 加 `不全=`。
- **分页器认不出 = 长书永远只有第一页，而且静默**（11-22）。`_next_page_url` 只认「同模板 +
  末段数字连续递增」，三种主流形状全不认（杰奇 `/html/1/9001_2/`、数字槽位 `/book/57620/2/`、
  下划线文件 `/0/98/index_2.html`）；`_merge_paged` 收尾只在「撞页数上限」置 `pending`，
  **墙钟到点/模板不符都静默退出**。凡"循环里提前退出"的分支，都要问：它退出时，**下游怎么
  知道它没做完**？
- **核实与下载的需求是相反的，不能共用一根旋钮**（11-22）。探测要"够判断"（3 页/3s），
  下载要"够完整"（40 页/25s）；原来共用 `get_chapters()` → 核实吃掉 20s+，压到 3 页又截书。
  已拆 `read_toc(full=False/True)`。

## 工具与环境的坑
- **Windows 上「管道/重定向」= GBK，而 Linux 永远复现不出来**（11-13）。启动横幅里的 `⇄`
  在 cp936 里没有 → `print()` 抛 UnicodeEncodeError → 进程在 `uvicorn.run()` **之前**就退，
  守护脚本每 60 秒再拉一次，一上午 542 次。修法不是删字符，是**加固 stdio**（只放宽 `errors`，
  编码得了的流一个字节不动）。凡"只在某个平台/某种 stdio 下才炸"的 bug，判据必须自己
  **构造那个环境**（`PYTHONIOENCODING=gbk`）。
- **真机套件用 `--no-check` 起服务 = 唯一会崩的那条分支从来没被走过**（11-13）。两问：
  ① 我的测试是不是恰好绕过了出问题的那条路？② 失败时，报错里有没有原因？
- **有测试 ≠ 有保护：判据必须登记进 ship 的清单**（11-15）。`tools/test_sched.py` 312 行、
  断言也不差，却**从没进过 `STATIC_SUITES`** → 每天都不跑，等于零保护。听到"我们早就有
  判据了"，先 `grep <文件名> tools/ship.py tools/mutate.py`。同母题另一种：**账只在返回值里，
  日志/状态接口里没有** —— 定时任务直接调 `ranks.refresh()`，`pending` 就丢了。
- **「默认超时」是隐形的墙钟**（11-15）。`fetch_text` 默认 25s 而榜单整轮预算也是 25s
  → 一个慢源吃掉整轮；查法：每个 `fetch_text(` 调用点问"上面有没有 `fast_mode`/预算"。
- **「主机级不可达」≠「产品挂了」**（11-13）。产品崩了端口给 `refused`（有回包）；连拒绝都没有、
  四个端口一致全超时、ICMP 也不回 → 实例不在线/安全组/路由。要说清是"主机不见"还是"进程不见"。
- **开工先 `git status`**（11-13）。工作区里躺着没还原的突变注入
  （`app/engine.py` 的 `tight_streamed` 被改成 `streamed`，正是 `mutate.py 召回` 第 5 条）——
  在脏树上跑 ship 等于拿被破坏的代码上线。
- `env -u http_proxy … python -c "多行"` 在本机 Git Bash 下静默无输出 → 用 `unset … ; python …` 或写文件。
  **`ssh` 同样中招**：`env -u … ssh … 'cmd'` 返回空且 exit=0，看起来像"服务器没日志"。ssh 直接打。
- 本机 `curl` 打线上返回空（连 `-w` 都不打印）→ 用 `.venv/Scripts/python.exe` + urllib。
- `tools/mutate.py` 与 `tools/ship.py` **不能并发**；看到"测试期间源码被外部改动"先查别的会话。
