## 主线：缓存 ≠ 去重（同一母题第三次）
复现：两个线程同时进 `discovery.page_of()`，把 `webfetch.analyze` 换记账慢桩 →
**analyze 被调用 2 次**。长书一次解析 21 页，两份 42 页，就是 11-22 那次线上 107s。

根因一句话：**缓存只在"跑完之后"才有值**。冷缓存下 N 个同 key 请求全部 miss、各自重做。
两个入口：`page_of()`（无合并）+ `utils.cached()`（producer 完全没合并，7 个调用点全是目录级：
configured / kunnu8×2 / template_source / wikisource / wyshu / xbqg5200）。

修：`utils.single_flight(key, producer)`（跑完即摘，不是缓存；领跑失败时等待者自己重跑；
领跑卡死 60s 后自己跑；同线程重入直接跑；`flight_stats` + 合并日志）；
`cached()` 接入并把缓存时间改成完成时刻；`page_of()` key = `pg{0|1}:{url}`（full 必须进 key）。

同类还查了 4 处：搜索（11-01 已有）、章节预取、wyshu 索引（11-15 已有）、page_of/cached（今天补）。
