## 主线（不依赖线上流量）
**「我们自己的限流冷却」被当成「源挂了」**。证据在本地实例日志里当场复发：
```
09:51:31 xbqg5200 返回空壳页面（59 字节），判定为限流并进入冷却 120s
09:51:33 source.fail 源=xbqg5200 "RuntimeError: 该站点刚被限流，冷却中（还剩 118s）"
09:51:48 WARNING 源 xbqg5200 连续失败，熔断 5 分钟
```
自噬循环：打太快 → 站给空壳 → 我们自限流 120s（对）→ 冷却期内每搜一次记一次失败（错）
→ 3 次满 → 熔断 300s（>120s）→ streak+1 → 10/20/40 分钟 → 越保护越死。

修：
- `errors.LocalCooldown`（RuntimeError 子类）+ `is_local_cooldown()`，同时认异常对象与
  `take_error()` 交回的字符串（两条入口）。
- `utils.fetch_text` 冷却期抛它；engine 两处失败记账都先判它（不 note_fail、不进 `挂`、
  日志走新事件 `source.skip`）；`search.done` 增第六格 `自限=`。
- 同一母题第二处：`ranks._fetch_source` 也不再记成榜单来源失败。
- 副线：榜单调度算术不平（7 类 / 3 并发 = 3 批 × 单类最坏 12.8s = 38.4s ≫ 25s）→
  `RANKS_FETCH_RETRIES = 0`，最坏 18s < 25s。逐类实测正常 0.25~3.83s、7 类串起来 11.87s。
